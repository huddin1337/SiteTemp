1.1 Why STP Exists

Without STP, redundant Layer 2 links create catastrophic switching loops: - Broadcast storms — broadcasts loop forever, growing exponentially - MAC table instability — same source MAC seen on multiple ports - Multiple frame copies — receivers get duplicates, applications break - Ethernet frames have no TTL — a looped frame circulates until the network crashes

STP solves this by blocking redundant links while keeping them available as backup.

1.2 STP Key Terms (MEMORIZE)

Term Definition
Root bridge Switch with the lowest Bridge ID — all STP decisions are from its perspective
Bridge ID (BID) 8 bytes = Priority (2B) + MAC address (6B). Lower = better. Default priority = 32,768
BPDU Bridge Protocol Data Unit — STP's hello message (sent every 2 seconds)
Root port (RP) Port on a non-root switch with the lowest cost path to root (one per switch)
Designated port (DP) Forwarding port on each network segment (one per segment)
Non-designated port Higher-cost port — goes Blocking to prevent loops
Port cost Cost of a single link (based on bandwidth)
Path cost Sum of all port costs from a switch to the root bridge

1.3 STP Port States (IEEE 802.1d)

State Forwards Frames? Learns MACs? Purpose
Disabled No No Admin shutdown — not participating
Blocking No No Prevents loops; listens to BPDUs only
Listening No No Transitioning; checks for loops
Learning No Yes Building MAC table before forwarding
Forwarding Yes Yes Normal operation

📌 MAC table is populated in Learning and Forwarding states only. 📌 Default 802.1d convergence: 50 seconds (20 max-age + 15 listening + 15 learning).

1.4 STP Link Costs (MEMORIZE)

Speed Cost
10 Mb/s 100
100 Mb/s 19
1 Gb/s (1000 Mb/s) 4
10 Gb/s 2

📌 Lower cost = better path. The root port is always the one with the lowest accumulated cost to the root bridge.

1.5 Root Bridge Election

  1. All switches start sending BPDUs every 2 seconds
  2. Switches compare Bridge IDs (priority + MAC)
  3. Lowest BID wins — that switch becomes the root bridge
  4. All ports on the root bridge are Designated Forwarding ports

Setting the Root Bridge

S2(config)#spanning-tree vlan 2 priority 16384        ! lower = better
! OR more elegantly:
S2(config)#spanning-tree vlan 3 root primary           ! auto-sets lowest priority
S2(config)#spanning-tree vlan 3 root secondary         ! sets backup priority

📌 PVST+ priority is configured in increments of 4096 (range 0–61440). Priority 0 = always root (if MAC is lower than any other switch at 0).

1.6 Types of Spanning Tree Protocols (MEMORIZE ALL FOUR)

Protocol Standard Per-VLAN? Convergence Resources
CST (Common STP) IEEE 802.1d No (1 instance) ~50 sec Low
PVST+ Cisco proprietary Yes ~50 sec Medium
RSTP IEEE 802.1w No (1 instance) Fast (~seconds) Medium
Rapid PVST+ Cisco (802.1w based) Yes Fast High (most)

📌 Cisco IOS default = PVST+ (802.1d per-VLAN). Enable Rapid PVST+ with spanning-tree mode rapid-pvst.

1.7 RSTP (802.1w) — Key Differences from 802.1d

802.1d State 802.1w State
Disabled Discarding
Blocking Discarding
Listening Discarding
Learning Learning
Forwarding Forwarding

💡 RSTP collapses Disabled/Blocking/Listening into Discarding. Only 3 states: Discarding → Learning → Forwarding.

RSTP Port Roles

Role Equivalent Description
Root port Root port Lowest cost to root
Designated port Designated port Best port on each segment
Alternate port Blocked port Backup to root port (ready to take over instantly)
Backup port Blocked port Redundant port on same segment

💡 RSTP's Alternate port can move to forwarding instantly without waiting for timers — this is why RSTP converges so fast.

Enabling RSTP

Switch(config)#spanning-tree mode rapid-pvst

Verifying STP

Switch#show spanning-tree
Switch#show spanning-tree vlan 1
Switch#show spanning-tree summary

1.8 PortFast

PortFast skips the Blocking → Listening → Learning delay and transitions directly to Forwarding. Use only on access ports connected to end devices (PCs, servers, printers).

Why PortFast?

  • Normal STP takes ~30 seconds from port up to forwarding
  • DHCP discovery times out during that delay → host gets no IP
  • PortFast = instant green light for end devices

Configure PortFast

! Global (all non-trunking access ports):
S1(config)#spanning-tree portfast default

! Per interface (preferred — more surgical):
S1(config)#interface gi0/1
S1(config-if)#spanning-tree portfast

⚠️ NEVER enable PortFast on a port connected to another switch. If a loop is formed, STP won't protect you because the port bypasses convergence checks.

1.9 BPDU Guard

BPDU Guard protects PortFast ports. If a BPDU is received on a PortFast-enabled port, the port immediately goes err-disabled — preventing someone from accidentally plugging in a switch.

! Global (on all PortFast ports):
S1(config)#spanning-tree portfast bpduguard default

! Per interface:
S1(config-if)#spanning-tree bpduguard enable

📌 Best practice: Always pair PortFast with BPDU Guard. Configure both globally on access switches.

1.10 Other STP Security Features (Exam Topic 2.5.d)

Feature Purpose Where to Use
BPDU Guard Err-disables port if BPDU received on PortFast port Access ports
BPDU Filter Stops sending/receiving BPDUs on a port Access ports (use carefully)
Root Guard Prevents a port from becoming the root port (rejects superior BPDUs) Downlink ports from distribution to access
Loop Guard Prevents a port from transitioning to forwarding if it stops receiving BPDUs Blocking ports on point-to-point links 
! Root Guard (per interface):
S1(config-if)#spanning-tree guard root

! Loop Guard (global):
S1(config)#spanning-tree loopguard default

📌 Root Guard protects the root bridge — prevents an access-layer switch from claiming to be the root by sending superior BPDUs.

1.11 EtherChannel (Exam Topic 2.4)

EtherChannel bundles 2–8 physical links into one logical link. Benefits: - STP sees it as one link → no blocking on bundled links - More bandwidth (combined throughput) - Redundancy — if one member port fails, others keep working - Routing protocols form one adjacency over the bundle

Negotiation Protocols

Protocol Type Modes
PAgP (Port Aggregation Protocol) Cisco proprietary desirable (active) / auto (passive)
LACP (Link Aggregation Control Protocol) IEEE 802.3ad (open standard) active (active) / passive (passive)

Mode Compatibility Matrix

Side A Side B PAgP Result LACP Result
desirable desirable Channel —
desirable auto Channel —
auto auto No channel —
active active — Channel
active passive — Channel
passive passive — No channel
on on Channel (static) Channel (static)

📌 Exam pattern: "passive + passive = no channel" for LACP; "auto + auto = no channel" for PAgP. One side must actively negotiate.

Configuring EtherChannel (LACP — Exam Standard)

! Step 1: Configure physical interfaces the same way
S1(config)#interface range gi0/1 - 2
S1(config-if-range)#switchport trunk encapsulation dot1q
S1(config-if-range)#switchport mode trunk
S1(config-if-range)#channel-group 1 mode active          ! LACP active

! Step 2: Configure the port-channel interface
S1(config)#interface port-channel 1
S1(config-if)#switchport trunk encapsulation dot1q
S1(config-if)#switchport mode trunk
S1(config-if)#switchport trunk allowed vlan 1,2,3

⚠️ All EtherChannel member ports must have identical configuration: speed, duplex, VLAN info, trunking mode.

Verifying EtherChannel

S2#show etherchannel port-channel
S2#show etherchannel summary
S2#show interfaces port-channel 1

Exam Essentials

  • ✅ STP purpose — prevents Layer 2 loops; elects root bridge; blocks redundant ports
  • ✅ Bridge ID = Priority + MAC — lowest wins root election
  • ✅ Default priority = 32,768; PVST+ adds VLAN ID (sys-id-ext) to the priority field
  • ✅ STP port states — Disabled / Blocking / Listening / Learning / Forwarding
  • ✅ 802.1d convergence = ~50 seconds. 802.1w (RSTP) is near-instant
  • ✅ RSTP states — Discarding / Learning / Forwarding (3 only)
  • ✅ Four STP types — CST, PVST+, RSTP (802.1w), Rapid PVST+
  • ✅ PortFast — instant forwarding for access ports; never use on switch-to-switch links
  • ✅ BPDU Guard — err-disables PortFast port when BPDU received
  • ✅ Root Guard / Loop Guard — upstream topology protection
  • ✅ EtherChannel — bundles links; STP sees it as one; LACP = open standard; PAgP = Cisco
  • ✅ LACP modes — active/passive; active+active OR active+passive = channel forms

Common Exam Gotchas

  1. Default STP priority = 32,768. PVST+ sys-id-ext adds the VLAN ID → effective priority = 32768 + VLAN.
  2. Root bridge = lowest BID (priority first, then MAC as tiebreaker).
  3. All ports on root bridge are Designated Forwarding — no root ports, no blocking.
  4. Every non-root bridge has exactly one root port.
  5. 802.1d = ~50 sec convergence. 802.1w/RSTP = seconds.
  6. RSTP states: Discarding / Learning / Forwarding only. 802.1d has 5.
  7. PortFast only for end devices — never for uplinks to other switches.
  8. BPDU Guard err-disables the port — recover with shutdown then no shutdown.
  9. LACP is the IEEE standard (802.3ad). PAgP is Cisco-only.
  10. active + passive = LACP channel. passive + passive = no channel.
  11. EtherChannel member ports must match: speed, duplex, VLAN, trunk mode.
  12. channel-group assigns port to bundle; interface port-channel creates the logical interface.
  13. Root Guard prevents a neighbor from becoming root (rejects superior BPDUs).
  14. Loop Guard prevents forwarding when BPDUs stop arriving (link may be unidirectional).
  15. BPDU Filter stops sending BPDUs — dangerous; use with caution.

Exam Topics Covered - 5.6 Configure and verify access control lists

⚠️ ACLs are one of the most heavily tested CCNA topics. Expect simlets where you must interpret or write ACL rules, determine permit/deny logic, and identify where to place an ACL.

2.1 What Is an ACL?

An Access Control List (ACL) is a set of rules that filters IP packets on a router interface. Each rule is a permit or deny statement evaluated top-to-bottom — the first match wins.

ACL Rules (MEMORIZE)

  1. Rules evaluated top to bottom — first match ends processing
  2. Implicit deny all at the bottom — if no rule matches, packet is dropped
  3. One ACL per interface, per direction (inbound OR outbound)
  4. Place standard ACLs close to the destination
  5. Place extended ACLs close to the source
  6. Cannot reorder entries within a named ACL without deleting and rewriting (unless sequence numbers are used)

2.2 ACL Types

Type Filters On Number Range
Standard Source IP only 1–99 and 1300–1999
Extended Source IP, Destination IP, Protocol, Port 100–199 and 2000–2699
Named Same as standard or extended, but named (easier to edit) Named string

2.3 Standard ACLs — Source IP Only

Standard ACL Syntax

Router(config)#access-list <1-99> {permit|deny} <source> [wildcard]

Examples

! Deny host 192.168.10.5, permit everything else:
Router(config)#access-list 10 deny 192.168.10.5 0.0.0.0
Router(config)#access-list 10 permit any

! Permit only 192.168.30.0/24 network:
Router(config)#access-list 30 permit 192.168.30.0 0.0.0.255
! (implicit deny any follows)

! Using "host" and "any" keywords:
Router(config)#access-list 10 deny host 10.0.0.5      ! = 10.0.0.5 0.0.0.0
Router(config)#access-list 10 permit any               ! = 0.0.0.0 255.255.255.255

📌 host X.X.X.X = wildcard 0.0.0.0 (exact match) 📌 any = 0.0.0.0 255.255.255.255 (match everything)

Wildcard Masks

Wildcard mask: 0 = must match, 1 = don't care - Wildcard = 255.255.255.255 − subnet mask - /24 (255.255.255.0) → wildcard = 0.0.0.255 - /25 (255.255.255.128) → wildcard = 0.0.0.127

Apply Standard ACL to Interface

Router(config)#interface fa0/0
Router(config-if)#ip access-group 10 in     ! inbound on fa0/0
Router(config-if)#ip access-group 10 out    ! outbound on fa0/0

📌 Standard ACLs → place close to DESTINATION (they only filter on source IP, so placing them near source would block traffic to ALL destinations)

2.4 Extended ACLs — Full Control

Extended ACL Syntax

Router(config)#access-list <100-199> {permit|deny} <protocol> <source> <src-wildcard> <destination> <dst-wildcard> [operator port]

Protocol Keywords

Keyword What It Matches
ip Any IP traffic
tcp TCP only
udp UDP only
icmp ICMP (ping)
ospf OSPF routing protocol

Port Operators

Operator Meaning
eq 80 Equal to port 80
ne 80 Not equal to port 80
lt 1024 Less than port 1024
gt 1023 Greater than port 1023
range 80 443 Port range 80 to 443

Extended ACL Examples

! Deny Telnet (TCP 23) from any to 192.168.30.0/24:
Router(config)#access-list 110 deny tcp any 192.168.30.0 0.0.0.255 eq 23
Router(config)#access-list 110 permit ip any any

! Deny ping (ICMP) from host 10.0.0.5 to any:
Router(config)#access-list 110 deny icmp host 10.0.0.5 any
Router(config)#access-list 110 permit ip any any

! Permit only HTTP (TCP 80) from 10.0.0.0/24 to server 172.16.1.100:
Router(config)#access-list 100 permit tcp 10.0.0.0 0.0.0.255 host 172.16.1.100 eq 80
Router(config)#access-list 100 deny ip any any

📌 Extended ACLs → place close to SOURCE (they can be specific enough to only block targeted traffic)

2.5 Named ACLs

Named ACLs are the preferred modern method — easier to read, edit with sequence numbers.

Named Standard ACL

Router(config)#ip access-list standard BLOCK-TELNET
Router(config-std-nacl)#deny host 192.168.10.5
Router(config-std-nacl)#permit any

Named Extended ACL

Router(config)#ip access-list extended ALLOW-WEB
Router(config-ext-nacl)#permit tcp 10.0.0.0 0.0.0.255 any eq 80
Router(config-ext-nacl)#permit tcp 10.0.0.0 0.0.0.255 any eq 443
Router(config-ext-nacl)#deny ip any any

Router(config-ext-nacl)#no 30                  ! delete entry 30

2.8 ACL for VTY Lines (Restrict Management Access)

Router(config)#access-list 50 permit 192.168.10.0 0.0.0.255
Router(config)#line vty 0 15
Router(config-line)#access-class 50 in

📌 access-class is used for VTY lines (not ip access-group). This restricts which source IPs can Telnet/SSH to the router.

Exam Essentials

  • ✅ Standard ACL — filters source IP only; numbered 1–99, 1300–1999; place near destination
  • ✅ Extended ACL — filters source, dest, protocol, port; numbered 100–199, 2000–2699; place near source
  • ✅ Named ACLs — preferred; allow sequence-number editing
  • ✅ Implicit deny all — at the bottom of every ACL; packet dropped if no match
  • ✅ First match wins — order of rules is critical
  • ✅ host X = 0.0.0.0 wildcard; any = 255.255.255.255 wildcard
  • ✅ One ACL per interface per direction (in or out)
  • ✅ Apply to interface with ip access-group; apply to VTY with access-class
  • ✅ Verify with show ip access-lists and show ip interface

Common Exam Gotchas

  1. Implicit deny all is always at the end — forgetting permit any at the end of a list blocks everything.
  2. Standard ACL number: 1–99 and 1300–1999. Extended: 100–199 and 2000–2699.
  3. Standard ACLs go near the DESTINATION. Extended ACLs go near the SOURCE.
  4. First match wins — a permit any before a deny makes the deny unreachable.
  5. host X.X.X.X is shorthand for X.X.X.X 0.0.0.0; any = 0.0.0.0 255.255.255.255.
  6. Wildcard 0 = must match, 1 = don't care. Wildcard is the INVERSE of a subnet mask.
  7. ip access-group applies to interfaces; access-class applies to VTY lines.
  8. permit ip any any and permit any are different — permit ip any any is extended; permit any is standard.
  9. Show ip access-lists shows hit counters — useful for verifying which rules are matching.
  10. Extended ACL eq applies to destination port by default when placed after the destination address.

📌 IPv6 is a major CCNA exam topic. The exam includes multiple IPv6 configuration and address-type questions.

3.1 Why IPv6?

  • IPv4 = 32 bits → ~4.3 billion addresses (exhausted)
  • IPv6 = 128 bits → 340 undecillion addresses (essentially infinite)
  • No need for NAT (every device gets a globally routable address)
  • Built-in IPsec support
  • Simplified header (no checksum, no fragmentation by routers)
  • Stateless Address Autoconfiguration (SLAAC) — no DHCP required

3.2 IPv6 Address Format

128 bits written as 8 groups of 4 hex digits separated by colons:

2001:0DB8:0000:0001:0000:0000:0000:0001

Two Abbreviation Rules

  1. Leading zeros in a group can be omitted: 0001 → 1, 0000 → 0
  2. One consecutive all-zero group sequence → :: (can only use once per address)
Full:         2001:0DB8:0000:0001:0000:0000:0000:0001
Rule 1:       2001:DB8:0:1:0:0:0:1
Rule 1+2:     2001:DB8:0:1::1

📌 :: can only appear once in an IPv6 address.

IPv6 Prefix Notation

IPv6 uses CIDR notation: 2001:DB8::/32 (prefix = first 32 bits)

3.3 IPv6 Address Types (MEMORIZE)

Type Range / Format Purpose
Global Unicast 2000::/3 (starts with 2 or 3) Public routable IPv6 (like public IPv4)
Unique Local FC00::/7 (FC or FD) Private IPv6 (like RFC 1918); not routed on Internet
Link-Local FE80::/10 On-link only; auto-configured; NOT routable
Multicast FF00::/8 One-to-many; replaces broadcast
Anycast Same range as unicast Assigned to multiple interfaces; routes to nearest
Loopback ::1/128 Same as 127.0.0.1 in IPv4
Unspecified ::/128 Source address when no address configured

📌 No broadcast in IPv6 — replaced by multicast. 📌 Link-local addresses start with FE80 and are required on every IPv6 interface.

3.4 Global Unicast Address Structure

| Global Routing Prefix (48 bits) | Subnet ID (16 bits) | Interface ID (64 bits) |
|    Assigned by ISP               |  You choose          |  Host portion          |

ISP assigns you a /48 prefix. You subnet within the 16-bit subnet field → 65,536 /64 subnets.

3.5 Link-Local Addresses

  • Auto-configured on every IPv6-enabled interface (no manual config needed)
  • Format: FE80::/10 + interface ID
  • Scope: on-link only — routers never forward link-local traffic
  • Used for: neighbor discovery, router discovery, routing protocol hellos
Router(config)#interface gi0/0
Router(config-if)#ipv6 address fe80::1 link-local    ! manual
! OR the router auto-generates from MAC via EUI-64

3.6 EUI-64 — Generating the Interface ID

EUI-64 creates a 64-bit interface ID from a 48-bit MAC address: 1. Split the 48-bit MAC in half: 00:50:56 | BE:EF:01 2. Insert FF:FE in the middle: 00:50:56:FF:FE:BE:EF:01 3. Flip the 7th bit (Universal/Local bit) of the first byte: 00 → 02 4. Result: 0250:56FF:FEBE:EF01

Auto-Configure IPv6 Using EUI-64

Router(config-if)#ipv6 address 2001:DB8:1::/64 eui-64

Router calculates the 64-bit interface ID from its MAC address automatically.

📌 Exam shortcut: The ff:fe inserted in the middle and the 7th bit flip are the two key EUI-64 facts.

3.7 Stateless Address Autoconfiguration (SLAAC)

SLAAC allows IPv6 hosts to self-configure without DHCP: 1. Host generates a link-local address (FE80:: + EUI-64) 2. Host sends a Router Solicitation (RS) to FF02::2 (all-routers multicast) 3. Router replies with a Router Advertisement (RA) containing the /64 prefix 4. Host combines the prefix + its EUI-64 interface ID → full global unicast address

! Router must advertise the prefix via RA:
Router(config-if)#ipv6 address 2001:DB8:1::1/64
Router(config-if)#no ipv6 nd suppress-ra     ! ensure RAs are sent

3.9 Configuring IPv6 on Cisco Routers

3.11 Neighbor Discovery Protocol (NDP)

NDP replaces ARP in IPv6. Uses ICMPv6 messages:

Message Purpose IPv4 Equivalent
Router Solicitation (RS) Host asks for router info —
Router Advertisement (RA) Router sends prefix info —
Neighbor Solicitation (NS) "What's the MAC for this IPv6?" ARP Request
Neighbor Advertisement (NA) "Here's my MAC" ARP Reply
Redirect Inform host of better next-hop ICMP Redirect

📌 NDP uses multicast (not broadcast). NS messages go to the Solicited-Node multicast address (FF02::1:FF/104 + last 24 bits of target IPv6 address).

Exam Essentials

  • ✅ IPv6 = 128 bits; written as 8 groups of 4 hex digits
  • ✅ Two abbreviation rules — drop leading zeros; :: replaces consecutive zero groups (once only)
  • ✅ Global unicast starts with 2 or 3 (2000::/3)
  • ✅ Link-local = FE80::/10 — auto-configured, not routable, required on all interfaces
  • ✅ Unique local = FC00::/7 — private IPv6 (like RFC 1918)
  • ✅ Loopback = ::1/128 (IPv6 equivalent of 127.0.0.1)
  • ✅ No broadcast in IPv6 — replaced by multicast
  • ✅ EUI-64 = split MAC, insert FF:FE, flip 7th bit → 64-bit interface ID
  • ✅ SLAAC = hosts auto-configure from RA-advertised prefix + EUI-64 interface ID
  • ✅ NDP = IPv6 neighbor discovery (replaces ARP): NS/NA for MAC resolution, RS/RA for router discovery
  • ✅ ipv6 unicast-routing required to enable IPv6 routing on Cisco routers

Common Exam Gotchas

  1. :: can only appear once in an IPv6 address.
  2. Link-local (FE80::/10) is required on every IPv6 interface — it's auto-configured.
  3. Link-local addresses are NOT routable — they're on-link only.
  4. No broadcast in IPv6 — replaced by multicast.
  5. ipv6 unicast-routing must be configured before a router will route IPv6 packets.
  6. EUI-64 flips the 7th bit (Universal/Local bit) of the first MAC byte.
  7. Unique local (FC/FD) ≠ link-local (FE80). Both are "private" but serve different purposes.
  8. SLAAC provides address configuration but NOT DNS — need DHCPv6 or RDNSS for DNS.
  9. NDP uses ICMPv6, not UDP or TCP.
  10. IPv6 prefix notation: 2001:DB8::/32 means the first 32 bits are the prefix.

5.1 Why NAT?

  • IPv4 exhaustion — RFC 1918 private addresses not routable on the Internet
  • NAT translates private (inside) addresses to public (outside) addresses
  • Enables many hosts to share one public IP (PAT/overload)
  • Hides internal topology from the Internet (security benefit)
  • Downside: breaks end-to-end connectivity, complicates troubleshooting

5.2 NAT Terminology (MEMORIZE)

Term Definition
Inside local Private IP of an inside host (RFC 1918) — e.g., 192.168.1.10
Inside global Public IP representing an inside host on the outside — e.g., 203.1.1.5
Outside local IP of an outside host as seen from the inside network
Outside global IP of an outside host as seen from the outside network

💡 Simple way to remember: - Inside = your network; Outside = the Internet - Local = private/real IP; Global = translated/public IP - "Inside local → Inside global" is the translation that happens most often

5.3 Three Types of NAT

Type Description Use Case
Static NAT One-to-one mapping of private IP → public IP Servers needing permanent public IP
Dynamic NAT Pool of public IPs; inside hosts grab one when needed Multiple hosts, multiple public IPs
PAT (Port Address Translation) Many-to-one; uses port numbers to track connections Home/SOHO — many hosts, ONE public IP

📌 PAT = NAT Overload. Almost all consumer NAT is PAT. The most common type on the exam.

5.4 Configuring Static NAT

Maps one inside local address permanently to one inside global address.

! Step 1: Define the static translation
Router(config)#ip nat inside source static 192.168.10.10 203.1.1.5

! Step 2: Mark interfaces
Router(config)#interface fa0/0
Router(config-if)#ip nat inside              ! LAN interface

Router(config)#interface serial0/0
Router(config-if)#ip nat outside             ! WAN/Internet interface

5.5 Configuring Dynamic NAT (Pool)

Hosts grab a public IP from a pool on demand.

! Step 1: Define the pool of public IPs
Router(config)#ip nat pool MY-POOL 203.1.1.1 203.1.1.10 netmask 255.255.255.0

! Step 2: Define which inside hosts get translated (ACL)
Router(config)#access-list 1 permit 192.168.10.0 0.0.0.255

! Step 3: Link the ACL to the pool
Router(config)#ip nat inside source list 1 pool MY-POOL

! Step 4: Mark interfaces
Router(config)#interface fa0/0
Router(config-if)#ip nat inside
Router(config)#interface serial0/0
Router(config-if)#ip nat outside

📌 If the pool runs out of public IPs, new connections are dropped (no translation available).

5.6 Configuring PAT (NAT Overload)

Many inside hosts share ONE public IP using unique port numbers.

! Using the WAN interface IP as the public IP (most common):
Router(config)#access-list 1 permit 192.168.10.0 0.0.0.255
Router(config)#ip nat inside source list 1 interface serial0/0 overload

! Using a pool with overload:
Router(config)#ip nat inside source list 1 pool MY-POOL overload

📌 The keyword overload is what makes it PAT. Without it, it's dynamic NAT.

8.1 The Problem FHRPs Solve

Hosts use a single default gateway. If that gateway router fails: - All hosts lose internet/WAN access - Recovery requires manual intervention or wait for users to notice

First-Hop Redundancy Protocols (FHRPs) provide a virtual IP/MAC shared by multiple routers. If the active router fails, the standby takes over automatically — hosts never change their gateway config.

8.2 FHRP Types

Protocol Standard VIP Virtual MAC Notes
HSRP Cisco proprietary One VIP 0000.0C07.ACxx Most tested; Active/Standby
VRRP IEEE (RFC 5798) One VIP 0000.5E00.01xx Open standard; Master/Backup
GLBP Cisco proprietary One VIP Multiple virtual MACs Load balancing across routers

📌 HSRP is the most tested FHRP on CCNA.

8.3 HSRP — Hot Standby Router Protocol

How HSRP Works

  1. Routers in an HSRP group negotiate Active and Standby roles
  2. Active router owns the virtual IP (VIP) and virtual MAC
  3. Hosts use the VIP as their default gateway
  4. Active sends hello packets every 3 seconds; hold timer = 10 seconds
  5. If Standby doesn't hear from Active for 10 seconds → Standby becomes Active

HSRP Router States

State Description
Disabled Not participating
Init Starting up
Learn Waiting to hear the VIP from Active
Listen Monitoring; not Active or Standby
Speak Sending hellos; participating in election
Standby Backup to Active; ready to take over
Active Forwarding traffic; owns the VIP

Active/Standby Election

  1. Highest priority wins Active (default priority = 100)
  2. Tie → Highest IP address wins

Preemption

By default, HSRP is NOT preemptive — if a higher-priority router comes back online, it doesn't take over. Enable preemption to restore the intended Active:

Router(config-if)#standby 1 preempt

8.4 Configuring HSRP

! Router A (intended Active — higher priority):
R1(config)#interface gi0/0
R1(config-if)#ip address 192.168.1.2 255.255.255.0
R1(config-if)#standby 1 ip 192.168.1.1           ! VIP = group 1, IP = .1
R1(config-if)#standby 1 priority 110              ! higher than default 100
R1(config-if)#standby 1 preempt                  ! take over if comes back

! Router B (Standby):
R2(config)#interface gi0/0
R2(config-if)#ip address 192.168.1.3 255.255.255.0
R2(config-if)#standby 1 ip 192.168.1.1           ! same VIP and group
R2(config-if)#standby 1 priority 90              ! lower than R1

📌 Hosts configure 192.168.1.1 (the VIP) as their default gateway — never the real router IPs.

Track an upstream interface — if it goes down, lower HSRP priority to force a failover:

📌 GLBP is Cisco-proprietary. CCNA level: know it exists and provides load balancing (unlike HSRP/VRRP).

9.1 Why QoS?

Networks have limited bandwidth and variable traffic patterns. Without QoS: - Voice/video (latency-sensitive) competes equally with bulk file transfers - Packet loss, jitter, and delay ruin real-time applications

QoS = mechanism to prioritize certain traffic and guarantee acceptable quality for critical applications.

9.2 QoS Key Metrics

Metric Definition Impact
Bandwidth Capacity of the link Limits how much data can be sent
Delay Time for a packet to travel source → destination Real-time apps need <150ms one-way
Jitter Variation in delay VoIP needs <30ms jitter
Packet loss Packets dropped VoIP tolerates <1% loss

9.3 QoS Models

Model Description How It Works
Best Effort No QoS All packets treated equally; no guarantees
IntServ (Integrated Services) Per-flow reservations Uses RSVP to reserve bandwidth; doesn't scale
DiffServ (Differentiated Services) Class-based Mark traffic into classes; each router honors markings; modern standard

📌 DiffServ is the modern QoS model — scalable, widely deployed.

9.4 QoS Classification and Marking

Classification = identifying which traffic gets which treatment. Marking = tagging packets so downstream devices know how to treat them.

Layer 2 Marking — CoS (Class of Service)

  • 802.1Q header (VLAN-tagged frames) has a 3-bit CoS field (PCP — Priority Code Point)
  • Values 0–7 (higher = better priority)
  • Called 802.1p marking

Layer 3 Marking — DSCP (Differentiated Services Code Point)

  • In the IPv4 header's ToS (Type of Service) byte — 6 bits used for DSCP
  • 64 possible values (0–63)
  • Common DSCP values:
Traffic Type DSCP Value DSCP Per-Hop Behavior
Best effort (default) 0 Default Forwarding (DF)
VoIP payload 46 Expedited Forwarding (EF)
Video/voice signaling 34 AF41
Critical data 26 AF31
Low-priority bulk 10 AF11

📌 EF (DSCP 46) = highest priority — used for VoIP voice traffic.

9.5 QoS Tools (PHBs — Per-Hop Behaviors)

1. Classification and Marking

Identify and tag traffic as early as possible (ideally at the access layer).

2. Queuing (Congestion Management)

Multiple output queues — high-priority traffic drains first.

Queuing Method How It Works
FIFO Default — first in, first out; no prioritization
PQ (Priority Queuing) Strict priority — high-priority queue always drains first
WFQ (Weighted Fair Queuing) Weights queues; prevents starvation
CBWFQ (Class-Based WFQ) Guarantees minimum bandwidth per class
LLQ (Low Latency Queuing) CBWFQ + strict priority queue for voice — most common for VoIP

📌 LLQ = CBWFQ + priority queue. Best for networks with real-time voice/video.

3. Shaping (Traffic Shaping)

  • Buffers excess traffic until the rate drops within allowed limits
  • Traffic is delayed, not dropped
  • Used on the sending side to smooth traffic bursts

4. Policing

  • Drops (or marks down) traffic that exceeds the configured rate
  • Traffic is discarded, not delayed
  • Used on the receiving side (or by ISPs to enforce SLAs)
Shaping Policing
Exceeds rate → Buffer/delay Drop or re-mark
Applied at Sender Receiver / Service Provider
Introduces delay Yes No

5. Congestion Avoidance (WRED)

  • WRED (Weighted Random Early Detection) proactively drops lower-priority packets before the queue is full
  • Signals TCP to slow down before congestion reaches crisis level
  • Without WRED: queue fills → tail drop → TCP global synchronization

9.6 Trust Boundaries

Where do you trust the QoS markings in incoming packets?

  • Access layer switch = ideal trust boundary (closest to endpoint)
  • IP phones: trusted (mark voice DSCP 46)
  • PCs: untrusted (may try to mark their own traffic as high priority)
! Trust DSCP markings from IP phones but not PCs:
Switch(config-if)#mls qos trust dscp             ! for phone ports

13.4 VRF (Virtual Routing and Forwarding)

VRF creates multiple independent routing tables on a single router — like virtual routers inside one physical router.

Why VRF?

  • Traffic separation — different customers or departments on same physical router
  • Overlapping IP addresses — MPLS VPNs use VRF to allow same IP space across customers
  • Network segmentation without extra hardware

VRF Types

Type Description
VRF (classic) Separate routing table; no MPLS
VRF-Lite Same as VRF but without MPLS; used in enterprise segmentation
VRF for MPLS Used by service providers for L3 MPLS VPNs

Configuring VRF-Lite

! Create VRFs:
Router(config)#vrf definition CUSTOMER_A
Router(config-vrf)#address-family ipv4
Router(config-vrf-af)#exit

Router(config)#vrf definition CUSTOMER_B
Router(config-vrf)#address-family ipv4

! Assign interfaces to VRFs:
Router(config)#interface gi0/0
Router(config-if)#vrf forwarding CUSTOMER_A
Router(config-if)#ip address 10.1.1.1 255.255.255.0

! Routing per VRF:
Router(config)#router ospf 1 vrf CUSTOMER_A
Router(config-router)#network 10.1.0.0 0.0.255.255 area 0

Verifying VRF

Router#show ip vrf
Router#show ip route vrf CUSTOMER_A
Router#ping vrf CUSTOMER_A 10.1.1.2

Exam Essentials

  • ✅ Hypervisor = software creating VMs; Type 1 = bare metal; Type 2 = hosted
  • ✅ VMs have full guest OS; Containers share host kernel — lighter and faster
  • ✅ Docker = containers; Kubernetes = container orchestration
  • ✅ VRF = multiple routing tables on one router (virtual router segmentation)
  • ✅ VRF-Lite = VRF without MPLS — enterprise segmentation use case

Common Exam Gotchas

  1. Type 1 hypervisor runs ON hardware (bare metal). Type 2 runs IN a host OS.
  2. Containers share the host OS kernel — no guest OS. This is what makes them lightweight.
  3. VRF isolates routing tables — same router, different routing instances.
  4. vrf forwarding X must be configured on the interface BEFORE the IP address.
  5. ping vrf X — must specify VRF when testing VRF connectivity.

14.1 Traditional vs. SDN Networking

Traditional Networking

  • Distributed control plane — each device makes its own forwarding decisions
  • Manual configuration per device (CLI)
  • Changes require touching individual devices
  • Hard to automate; configuration drift common

SDN (Software-Defined Networking)

  • Centralized control plane — a controller makes network-wide decisions
  • Devices become simpler data-plane forwarders
  • Policy and changes pushed from controller to all devices
  • Programmable via APIs

14.2 SDN Planes

Plane Function Traditional SDN
Control plane Makes routing/forwarding decisions Distributed (each device) Centralized (controller)
Data plane Forwards packets based on control plane rules Same device Same device (hardware)
Management plane Device configuration and monitoring CLI/SNMP per device Northbound API from controller

14.5 Spine-Leaf Architecture (Exam Topic 1.2c)

Modern data center topology replacing traditional three-tier (Core-Distribution-Access):

         Spine 1    Spine 2
        /  \  /  \  /      Leaf1  Leaf2  Leaf3  Leaf4
     |       |       |       |
   Servers Servers Servers Servers

Rules

  • Every Leaf connects to every Spine
  • Leaf switches connect to servers, storage, other edge devices
  • Spine switches only connect to Leaves (never to other Spines)
  • Any server-to-server path is always 2 hops (Leaf → Spine → Leaf)

Advantages

Advantage Traditional Three-Tier Spine-Leaf
Latency Variable (varies by path) Consistent (always 2 hops)
East-West traffic Bottleneck at core Optimized
Scalability Limited Add Leaf = more servers; Add Spine = more bandwidth

📌 East-West traffic = server-to-server within data center (most modern data center traffic is east-west, not north-south to/from Internet).

15.2 Data Formats (Exam Topic — KNOW ALL THREE)

Network automation tools exchange data in structured formats:

JSON (JavaScript Object Notation) — Most Common

{
  "hostname": "Router1",
  "interfaces": [
    {
      "name": "GigabitEthernet0/0",
      "ip": "192.168.1.1",
      "mask": "255.255.255.0"
    }
  ]
}
  • Key-value pairs
  • Human-readable
  • Most common in REST APIs
  • Curly braces {} = objects; square brackets [] = arrays

XML (Extensible Markup Language)

<router>
  <hostname>Router1</hostname>
  <interface>
    <name>GigabitEthernet0/0</name>
    <ip>192.168.1.1</ip>
  </interface>
</router>
  • Uses opening/closing tags (like HTML)
  • Used by NETCONF
  • More verbose than JSON

YAML (YAML Ain't Markup Language)

hostname: Router1
interfaces:
  - name: GigabitEthernet0/0
    ip: 192.168.1.1
    mask: 255.255.255.0
  • Very human-readable
  • Indentation-sensitive (spaces, NOT tabs)
  • Used in Ansible playbooks
  • Superset of JSON (valid JSON is valid YAML)

Configuration management (CM) = using software tools to define, deploy, and maintain device/system configuration consistently across a large infrastructure.
