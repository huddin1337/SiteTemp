1.1 What Is an Internetwork?

An internetwork is created when you connect two or more networks via a router and configure a logical addressing scheme using a protocol like IP or IPv6.

  • A LAN is contained within a small geographic area (one building, one office).
  • An internetwork is multiple LANs tied together by routers.
  • The "Inter" in "Internet" literally comes from this concept — it's a global internetwork.

1.2 LANs and SOHO Networks

SOHO (Small Office / Home Office)

A SOHO network is a single user or small group of users connecting to a switch, with a router providing Internet access — typically combined into a single all-in-one device (router + switch + Wi-Fi + firewall).

A basic SOHO network connected via a hub has two important properties:

Property Count Why
Collision domain 1 A hub forwards every signal out every port — collisions are guaranteed when two devices transmit at once
Broadcast domain 1 No router is present to stop broadcasts

Hubs (Legacy)

  • Operate at Layer 1 (Physical) only.
  • Multiport repeaters — they regenerate the electrical signal on every port.
  • Do not segment a network; they just connect cable segments.
  • A hub is a single collision domain AND a single broadcast domain.

📌 Exam tip: If you see "operates only at the Physical layer" → the answer is hub.

1.3 Causes of LAN Congestion

Common causes of LAN traffic congestion: - Too many hosts in a collision or broadcast domain - Broadcast storms - Excessive multicast traffic - Low bandwidth - Adding hubs for connectivity - Excessive ARP broadcasts

1.4 Switches (Layer 2)

Switches operate at Layer 2 (Data Link). They use specialized hardware called an ASIC (Application-Specific Integrated Circuit) to forward traffic at line rate with very low latency.

Latency = the time measured from when a frame enters a port to when it exits a port.

What Switches Do

  1. Break up collision domains — every switch port is its own collision domain.
  2. Build a MAC address table (also called a filter table or CAM table) by reading the source MAC of every incoming frame and recording which port it arrived on.
  3. Forward frames based on the destination MAC address:
  4. Known unicast → forward only out the port leading to that MAC
  5. Unknown unicast → flood out all ports except the one it came in on (then learn from the reply)
  6. Broadcast (FF:FF:FF:FF:FF:FF) → flood out all ports
  7. Multicast → flood out all ports by default (unless IGMP snooping is configured)

This selective forwarding behavior is called transparent bridging.

What Switches Do NOT Do

  • Do not break up broadcast domains by default → one switched LAN = one broadcast domain.
  • Do not forward packets between networks — they only switch frames within the same network.

📌 Exam gotcha: A broadcast storm can only be stopped by a router (Layer 3 device).

1.5 Routers (Layer 3)

Routers operate at Layer 3 (Network) and connect different networks (different IP subnets).

What Routers Do

  • Break up broadcast domains by default — they do NOT forward broadcasts.
  • Break up collision domains as well (every router interface is its own collision domain).
  • Use logical addresses (IP) to make forwarding decisions on packets.
  • Maintain a routing table mapping known networks to outgoing interfaces.
  • Can filter traffic at Layer 3 using access lists (ACLs).
  • Provide WAN connectivity (historically via a serial interface — V.35 on Cisco routers).

Two Key Advantages of Routers

  1. They do not forward broadcasts by default.
  2. They can filter the network based on Layer 3 (IP) information.

Switch (L2) Router (L3)

💡 Real-estate analogy: Routers care about neighborhoods (networks). Switches care about houses (individual devices).

1.7 Frames vs. Packets (Quick Reference)

Term Layer Addressing
Frame Layer 2 Source + destination MAC
Packet Layer 3 Source + destination IP

A packet is wrapped (encapsulated) inside a frame as it travels across a LAN. Think of a packet as a package containing data, and the frame as the delivery envelope on top of it.

1.8 Next-Generation Firewalls (NGFW) and IPS

Traditional Firewall vs. NGFW

  • Traditional firewall: Stateful inspection, mostly Layer 3–4 (IP, port, protocol). Cisco's older ASA is the classic example.
  • NGFW (third-generation): Adds full packet reassembly and deep packet inspection up to Layer 7, with little added latency ("bump in the wire").

Cisco's NGFW product line is Firepower (originally Sourcefire, acquired in 2013). The newer platform is Firepower Threat Defense (FTD).

What an NGFW Must Provide (Minimum)

  • Router and switch compatibility (L2/L3)
  • Packet filtering with IPS and malware inspection
  • NAT (Network Address Translation)
  • Stateful inspection
  • VPN support
  • URL and application filtering
  • QoS (Quality of Service)
  • Third-party integration
  • REST API support

Application Visibility and Control (AVC)

NGFWs can identify which application is generating traffic (not just the port), letting policy allow/block by app (e.g., allow Office 365, block BitTorrent).

Intrusion Prevention System (IPS)

  • IPS = inline, blocks malicious traffic in real time.
  • IDS (older) = monitors only and alerts; does not block. (Know the difference!)

SSL Decryption

NGFWs can decrypt SSL/TLS traffic to inspect it — but this requires hardware encryption acceleration to operate at wire speed (and it's expensive).

📌 Exam gotcha: NGFWs do not do "Layer 2 deep packet inspection" — there's no such thing. Packets are a Layer 3 concept. If you see "L2 packet inspection" as a feature, it's the wrong answer.

1.9 Network Topology Architectures

Hierarchy in network design brings predictability, scalability, and easier troubleshooting. Cisco defines three main campus architectures plus a data-center architecture.

⚠️ Important: These layers are logical, not physical. One device can perform two layers' functions; multiple devices can share one layer.

Three-Tier (Cisco Hierarchical Model)

            [ CORE ]          ← fast backbone
               |
        [ DISTRIBUTION ]      ← policy, routing, filtering
               |
           [ ACCESS ]         ← end users, phones, APs

Core Layer — "Switch traffic as fast as possible"

  • The backbone. Transports large volumes of traffic, reliably and quickly.
  • A failure here affects every user → fault tolerance is critical.
  • Typical speeds: 10G, 40G, 100G, often with redundant links.

Core Layer — DON'Ts - ❌ Don't use access lists (slows traffic) - ❌ Don't route between VLANs - ❌ Don't implement packet filtering - ❌ Don't support workgroup access - ❌ Don't expand by adding more devices — upgrade instead

Core Layer — DOs - ✅ Design for high reliability and redundancy - ✅ Design for speed and low latency - ✅ Choose routing protocols with fast convergence times

Distribution Layer (a.k.a. Workgroup / Aggregation Layer)

The communication point between access and core. This is the policy layer.

Responsibilities: - Routing between VLANs - Implementing ACLs, packet filtering, queuing - Security and network policies, NAT, firewalls - Redistribution between routing protocols (including static) - Defining broadcast and multicast domains - WAN access

Access Layer (a.k.a. Desktop Layer)

Where end users, phones, printers, and APs plug in.

Responsibilities: - Device connectivity - Microsegmentation (each port = own collision domain) - PoE (Power over Ethernet) for phones and APs - Port security - Continued enforcement of ACLs and policies from the distribution layer - Connectivity into the distribution layer - Resiliency and security services - Advanced services (voice, video) - Typical speeds: Fast Ethernet, Gigabit Ethernet

Two-Tier (Collapsed Core)

        [ CORE + DISTRIBUTION ]   ← merged ("collapsed")
                  |
              [ ACCESS ]
  • Distribution layer is merged with the core layer onto the same enterprise switch.
  • Same logical functions, fewer devices.
  • More economical — geared for small and medium-sized campuses.
  • Still functional and scalable for environments not expected to grow significantly.
  • Access switches connect to defined aggregation ports on the collapsed-core switch.

Spine-Leaf (Data Center)

        [ SPINE ]   [ SPINE ]   [ SPINE ]
           |  X        X  |        |
        [ LEAF ]   [ LEAF ]   [ LEAF ]
           |          |          |
        servers    servers    servers

Built for modern data centers where most traffic flows server-to-server (east-west), not client-to-server (north-south).

Key properties: - Leaf switches sit at the top of each rack → called Top-of-Rack (ToR) design. - Servers in the rack connect to the leaf switch (often two leaves for redundancy). - Every leaf connects to every spine. Leaves do NOT connect to each other; spines do NOT connect to each other. - Spines connect only to leaves — never to servers or end devices. - Result: every server is exactly one switch hop from any other server (predictable, low latency). - Scales by adding spines (more bandwidth) or leaves (more ports).

📌 Exam tip: Top-of-Rack (ToR) = spine-leaf. They're the same design.

Architecture Comparison

Architecture Layers Best For
Three-tier Core / Distribution / Access Large enterprise campuses
Two-tier (Collapsed Core) Core+Distribution / Access Small to medium campuses
Spine-Leaf Spine / Leaf Modern data centers
SOHO All-in-one device Home / very small office

1.10 Wide Area Networks (WANs)

LAN vs. WAN — The Real Distinction

LAN WAN
Ownership You own the infrastructure You lease from a service provider
Geographic scope Single site Large geographic area
Speeds 10/25/40/100 Gbps common Varies, typically lower
Examples Office, building MPLS, leased line, Internet circuit

💡 The most reliable distinguisher: you own a LAN; you lease a WAN.

Why WANs Are Needed

  • Regional and branch offices need to share data
  • Organizations need to share information across long distances
  • Mobile/traveling employees need access to corporate resources

Three Major Characteristics of WANs

  1. Connect devices separated by broader geographic areas than a LAN can serve.
  2. Use the services of carriers (telcos, cable companies, satellite, network providers).
  3. Use serial connections of various types to provide bandwidth over large distances.

2.1 What Is Ethernet?

Ethernet is a contention-based media access method that lets all hosts on a network share the same link's bandwidth.

Why it's dominant: - Simple to implement - Easy to troubleshoot - Highly scalable (you can mix 100 Mbps, 1 Gbps, 10 Gbps gear on the same network)

Ethernet operates at two OSI layers — Data Link (Layer 2) and Physical (Layer 1). You need both to implement, troubleshoot, and maintain an Ethernet network.

2.2 Collision Domains and Broadcast Domains (Review)

Collision Domain

A network segment where, if two devices transmit simultaneously, their signals interfere on the wire and a collision occurs — forcing retransmission.

  • Hub: 1 collision domain (all ports share it)
  • Switch: Each port = its own collision domain
  • Router: Each interface = its own collision domain

Broadcast Domain

A group of devices that hear all the broadcasts sent on a network segment.

  • Hub: 1 broadcast domain
  • Switch: 1 broadcast domain by default (use VLANs to break it up)
  • Router: Each interface = its own broadcast domain

Wireless Access Points (APs)

Operate at the same layer as a hub functionally — they extend a collision domain wirelessly but do not segment the network.

📌 Exam point: APs make your LAN bigger but don't break up broadcast or collision domains.

2.3 CSMA/CD — Carrier Sense Multiple Access with Collision Detection

CSMA/CD is the protocol used in half-duplex Ethernet to share bandwidth and recover from collisions. It does not eliminate collisions — it manages them.

How CSMA/CD Works (in order)

  1. Host wants to transmit — it listens (carrier sense) for a digital signal on the wire.
  2. If the wire is idle → it transmits.
  3. While transmitting, it continuously monitors the wire for collisions.
  4. If a collision is detected, the transmitting host sends an extended jam signal to inform all devices.
  5. All transmitting devices invoke a random backoff algorithm (each waits a different random time).
  6. Each device stops transmitting until its backoff timer expires.
  7. After timers expire, all hosts have equal priority to transmit again.
  8. After 15 failed retries, the nodes time out.

Effects of Heavy Collisions on CSMA/CD

  • Delay
  • Low throughput
  • Congestion

📌 Memorize the post-collision sequence — Cisco asks this in order: 1. Jam signal informs all devices 2. Random backoff algorithm invoked 3. Each device stops transmitting until backoff timer expires 4. Equal priority to transmit after timers expire

💡 Backoff = the retransmission delay enforced after a collision. After backoff elapses, all stations have equal priority.

2.4 Half-Duplex vs. Full-Duplex Ethernet

Half-Duplex

  • One wire pair, signal runs both directions on the same wire (Cisco's description).
  • Uses CSMA/CD to handle collisions.
  • Only ~30–40% efficient due to overhead (a "100Base-T" network often only delivers 30–40 Mbps).
  • A hub must run half-duplex.

Full-Duplex

  • Uses two wire pairs simultaneously — one for TX, one for RX.
  • Point-to-point connection between transmitter and receiver.
  • No collisions possible (TX and RX on different wires).
  • Theoretical aggregate efficiency: 100% in both directions (10 Mbps full-duplex = "20 Mbps aggregate"; 100 Mbps = "200 Mbps aggregate").
  • Requires both endpoints to be capable AND configured for full-duplex.

The Six Full-Duplex Scenarios (Memorize)

Full-duplex Ethernet can be used: 1. Switch ↔ Host 2. Switch ↔ Switch 3. Host ↔ Host 4. Switch ↔ Router 5. Router ↔ Router 6. Router ↔ Host

⚠️ You can run full-duplex on almost any device except a hub.

Auto-Detect (Auto-Negotiation)

When a port comes up, it negotiates with the remote end: 1. First decides speed (10, 100, 1000+ Mbps) 2. Then decides duplex (full or half) 3. If negotiation fails → falls back to 10 Mbps half-duplex

📌 Best practice: Hard-code speed and duplex on critical switch ports. Auto-negotiation failures are a common cause of duplex mismatches.

Duplex Mismatch (Exam Topic 1.4)

A duplex mismatch happens when one side is full-duplex and the other is half-duplex. - Half-duplex side sees "collisions" (because the full-duplex side transmits whenever it wants) - Symptoms: late collisions, FCS errors, slow throughput - The link still works — just badly. Hardest kind of issue to spot.

2.6 Ethernet at the Data Link Layer

The Data Link layer is responsible for: - Ethernet (MAC) addressing - Framing packets from the Network layer for transmission - Using the contention-based media access method (CSMA/CD on half-duplex)

MAC Address Anatomy

A MAC address is 48 bits (6 bytes) written in hexadecimal:

   OUI (24 bits)         |    Vendor-assigned (24 bits)
   00:60:f5              :    00:1f:27
   ↑                          ↑
   Assigned by IEEE           Unique per NIC (in theory)

The Two Important Bits in a MAC Address

Bit Name Meaning
High-order bit I/G (Individual/Group) 0 = unicast MAC of a device; 1 = broadcast or multicast
Next bit U/L (also G/L — Universal/Local) 0 = globally administered (by IEEE); 1 = locally administered

📌 Exam gotcha: "Which bit indicates locally vs. globally administered?" → U/L bit. Don't confuse it with the I/G bit.

💡 The OUI (first 3 bytes) is assigned by the IEEE to the manufacturer. The remaining 3 bytes uniquely identify the NIC.

2.8 Ethernet Frames

The Data Link layer combines bits → bytes → frames. Frames encapsulate packets handed down from the Network layer.

💡 Tunneling = encapsulating a frame inside a different type of frame.

Ethernet Frame Format

+----------+-----+-------------+-------------+---------------+-----------+-----+
| Preamble | SFD | Destination |   Source    | Length / Type |   Data    | FCS |
|  7 bytes |1byte|   6 bytes   |   6 bytes   |   2 bytes     | 46-1500 B |4byte|
+----------+-----+-------------+-------------+---------------+-----------+-----+

Field-by-Field Reference

Field Size Purpose
Preamble 7 bytes Alternating 1,0 pattern — provides clock so receiver can lock onto the bit stream
SFD / Synch 1 byte 10101011 — the last 11 lets receivers detect the start of actual data
Destination Address (DA) 6 bytes (48 bits) Receiving station's MAC. Can be unicast, broadcast (all Fs), or multicast
Source Address (SA) 6 bytes (48 bits) Transmitting station's MAC. Broadcast/multicast are illegal here.
Length or Type 2 bytes 802.3 uses Length; Ethernet_II uses Type to ID Network-layer protocol
Data 46–1500 bytes The packet from the Network layer
FCS 4 bytes Frame Check Sequence — holds CRC result for error detection

About FCS / CRC

  • FCS = the field at the end of the frame.
  • CRC = the algorithm that runs on the frame to produce the FCS value.
  • Sender runs CRC, puts answer in FCS. Receiver runs CRC on what it got — if the answers don't match, frame is dropped.
  • Error detection only — not error correction. Ethernet has no built-in retransmission; upper-layer protocols (like TCP) handle that.

Ethertype Values (Memorize)

Ethertype Protocol
0x0800 IPv4
0x86DD IPv6
0x0806 ARP

Identifying Frame Types

  • Ethernet_II uses a Type field → can identify upper-layer protocol → modern standard.
  • 802.3 (original) uses a Length field → cannot identify upper-layer protocol → legacy/IPX only.

Cable Type Used For

Straight-Through

Wiring: 1→1, 2→2, 3→3, 6→6 (10/100 Mbps uses pins 1, 2, 3, 6 only)

Use it for: - Host ↔ Switch - Host ↔ Hub - Router ↔ Switch - Router ↔ Hub

Crossover

Wiring: Cross 1→3 and 2→6

Use it for: - Switch ↔ Switch - Hub ↔ Hub - Hub ↔ Switch - Host ↔ Host - Router ↔ Router - Router ↔ Host (direct, no switch)

💡 Auto-MDIX is the auto-detect feature that lets straight-throughs work between switches, but CCNA objectives expect you to use the correct cable type — don't rely on auto-MDIX on the exam.

Rolled (Rollover / Console)

Wiring: Pinouts reversed end-to-end (pin 1 → pin 8, pin 2 → pin 7, etc.)

Use it for: - Host COM port ↔ Router/Switch console port (EIA-TIA 232 serial)

Gigabit Crossover (1000Base-T)

Common Exam Gotchas from This Chapter

  1. Source MAC cannot be a broadcast or multicast. Only destinations can.
  2. FCS does error detection, not correction. Bad frames are dropped, not fixed.
  3. U/L bit = locally vs. globally administered. I/G bit = unicast vs. broadcast/multicast. Don't mix them up.
  4. Ethertype 0x0800 = IPv4, 0x86DD = IPv6. Memorize both.
  5. Cat 6 only runs 55m at 10 Gbps — every other modern Cat does 100m. Cat 8 only runs 30m.
  6. Full-duplex has no collisions — period. (Not "few," not "rare" — none.)
  7. After CSMA/CD backoff, ALL hosts have equal priority — not just the ones involved in the collision. And the backoff algorithm runs on all systems, not just the colliders. (Note: this is a Lammle gotcha — real-world implementations only back off the involved nodes, but the CCNA book wants "all systems.")
  8. Auto-MDIX lets you "cheat" with straight-through between switches — but CCNA expects the correct cable per the table.
  9. Console settings: 9600 / 8 / None / 1 / None. The wrong one in a list is the question. ("Data bits: 1" = wrong, should be 8.)
  10. Single-mode = small core, long distance, expensive, laser. Multimode = big core, short distance, cheap, LED/laser.
  11. A socket = IP address + port number (TCP virtual circuit endpoint).
  12. APs extend a collision domain — they don't segment. Same broadcast domain as the switch they connect to.

3.1 The DoD Model vs. The OSI Model

The DoD model (also called the TCP/IP stack) is a condensed, 4-layer version of the 7-layer OSI model.

Layer Mapping

Telnet (Port 23, TCP)

  • Oldest remote-login protocol (1969).
  • Terminal emulation — makes the client appear as a directly attached terminal.
  • Sends everything in cleartext — including passwords. Never use in production.

SSH (Port 22, TCP) — Exam Topic 4.x

  • Modern replacement for Telnet, rsh, and rlogin.
  • Encrypted session over standard TCP/IP.
  • Used for remote login, running commands, transferring files.

FTP (Ports 20, 21, TCP)

  • Two ports: 21 = control (commands), 20 = data (file transfer).
  • Both a protocol and a program.
  • Supports authentication (username/password) and directory operations (cd, ls).
  • Limited functions — can't execute remote files as programs.
  • Can be used anonymously (login as anonymous) but with restricted access.

TFTP (Port 69, UDP)

  • "Trivial" FTP — stripped-down version.
  • No directory browsing, no authentication.
  • Smaller block sizes than FTP.
  • Heavily used to back up/restore Cisco IOS images and configurations.
  • Inherently insecure; rarely exposed to the Internet.

SMTP (Port 25, TCP)

  • Sending mail between mail servers.

POP3 (Port 110, TCP) and IMAP4 (Port 143, TCP)

  • Used by mail clients to retrieve mail.
  • POP3 downloads and (typically) removes mail from the server.
  • IMAP4 leaves mail on the server, supports folders, sync across devices.

SNMP (Port 161, UDP) — Exam Topic 4.4

  • Simple Network Management Protocol — polls and manipulates network device info.
  • A Network Management Station (NMS) polls devices for data.
  • Devices run agents.
  • When something goes wrong, the agent sends a trap to the NMS.
  • A baseline is a report describing the operational traits of a healthy network.

SNMP Versions

Version Notes
SNMPv1 UDP only. Mostly obsolete. Plaintext community strings.
SNMPv2 Added GETBULK (retrieve a large amount of data at once). Never really caught on.
SNMPv3 Current standard. Uses TCP and UDP. Adds security: message integrity, authentication, and encryption.

📌 Exam: v3 is the secure version. v1/v2 send community strings in cleartext.

HTTP (Port 80, TCP) and HTTPS (Port 443, TCP)

  • HTTP fetches resources via URLs.
  • HTTPS uses SSL/TLS to encrypt the session — used for forms, logins, banking.

NTP (Port 123, UDP)

  • Synchronizes clocks across devices to a common time source (e.g., an atomic clock).
  • Critical for logging, certificate validation, database consistency, Kerberos auth.
  • A few seconds of clock drift can break authentication entirely.

DNS (Port 53, TCP & UDP) — Exam Topic 4.3

Resolves hostnames to IP addresses.

How DNS Works

  1. Client types a URL → app hands it to the Application layer.
  2. Client sends a UDP request to its DNS server to resolve the name.
  3. If the local DNS server doesn't know, it forwards the query (usually via TCP for larger responses) to a root DNS server.
  4. The answer eventually returns to the originating host.
  5. Host connects to the actual server using the resolved IP.

FQDN (Fully Qualified Domain Name)

A complete hostname including all domain levels: www.lammle.com, todd.lammle.com.

To append a domain automatically on a Cisco router:

ip domain-name lammle.com

📌 Troubleshooting clue: If you can ping by IP but not by name → likely a DNS problem.

One computer with one IP can have many simultaneous sessions because the Transport layer tracks them by port number. That's how you can have three browser tabs to the same site at once.

3.5 Internet Layer Protocols

Three main protocols at the Internet layer: - IP — routing and logical addressing - ICMP — diagnostics and error messages - ARP — IP-to-MAC resolution

IP — Internet Protocol

What IP does: - Provides a logical address (IP address) to every host. - Uses a routing table to decide the best path. - Fragments segments into datagrams (packets) if needed. - Reassembles datagrams back into segments on the receiving side. - Adds source and destination IP to every datagram.

3.6 ICMP — Internet Control Message Protocol

ICMP is IP's management and messaging protocol. It's a Layer 3 protocol but its messages are carried inside IP datagrams.

Characteristics

  • Provides hosts with info about network problems.
  • Encapsulated inside IP datagrams.
  • Does NOT guarantee delivery — it's IP, after all.

Common ICMP Messages

Message Purpose
Destination Unreachable Router can't forward the packet (no route, host down, etc.)
Time Exceeded TTL hit zero — packet was killed before reaching destination
Buffer Full / Source Quench Router congestion notification (deprecated in modern networks)
Echo Request / Echo Reply Used by Ping
Redirect "Use a different gateway, this isn't the best path"

Ping

  • Uses ICMP Echo Request (Type 8) and Echo Reply (Type 0).
  • Tests physical and logical connectivity.
  • Payload is the alphabet (abcdefg...) — but Windows ping only goes A through W, then loops back to A. (Weird Microsoft quirk.)

Traceroute / Tracert

  • Discovers the path a packet takes through the network.
  • Sends packets with increasing TTL values (1, 2, 3, …) so each successive router has to send back a Time Exceeded message.
  • Microsoft Windows uses tracert instead of traceroute.

📌 Exam clue: ICMP is encapsulated in IP — so an ICMP packet has an IP Type/Protocol field of 0x01.

3.7 ARP — Address Resolution Protocol

ARP finds the hardware (MAC) address for a known IP address.

How ARP Works

  1. A host wants to send a packet but only knows the destination IP.
  2. It checks its ARP cache for that IP → MAC mapping.
  3. If not cached, it sends an ARP broadcast asking "Who has IP X? Tell me your MAC."
  4. The target host responds with its MAC address.
  5. The sender caches the result and sends the frame.

Key Details

  • ARP broadcasts use destination MAC ff:ff:ff:ff:ff:ff (all 1s).
  • ARP request Operation code = 1; ARP reply Operation code = 2.
  • ARP only works on the local network — routers don't forward ARP broadcasts.

Gratuitous ARP

A host ARPs for its own IP address to detect duplicates. Used by DHCP clients during the DORA process.

Reverse ARP (RARP)

Finds an IP from a known MAC. Mostly historical — replaced by BootP and DHCP.

📌 Quick rule: ARP = IP → MAC. RARP = MAC → IP.

A flat scheme would force every router to know every host on the Internet. Hierarchical (network + host) lets routers store only network entries.

📌 MEMORIZE the first octet ranges and the binary leading bits. Cisco exam loves this.

💡 Memory hook: Class A starts with 0, B with 10, C with 110, D with 1110, E with 1111.

Class A Specifics

  • Format: network.node.node.node
  • First byte = network; remaining 24 bits = hosts.
  • First bit must be 0 → 0xxxxxxx → 0 to 127.
  • 127 is reserved for loopback → usable range = 1 to 126.
  • 2⁷ − 2 = 126 Class A networks possible.
  • 2²⁴ − 2 = 16,777,214 hosts per Class A network.

Class B Specifics

  • Format: network.network.node.node
  • First two bits must be 10 → 128 to 191.
  • 2¹⁴ = 16,384 Class B networks.
  • 2¹⁶ − 2 = 65,534 hosts per Class B network.

Class C Specifics

  • Format: network.network.network.node
  • First three bits must be 110 → 192 to 223.
  • 2²¹ = 2,097,152 Class C networks.
  • 2⁸ − 2 = 254 hosts per Class C network.

The "−2" Rule

Every network "loses" two host addresses: - All host bits 0 = the network address itself (not usable for hosts). - All host bits 1 = the broadcast address.

So hosts per subnet = 2ⁿ − 2 where n = number of host bits.

  • Network address: Turn all host bits OFF (0).
  • Broadcast address: Turn all host bits ON (1).
  • Valid host range: Everything in between.

3.11 Private IP Addresses (RFC 1918) — Exam Topic 1.7

Private addresses are not routable on the Internet — they're for internal use only. They conserve public IP space and add a small layer of security.

  • Home networks: Use 192.168.x.x/24 — small, simple, plenty of hosts.

Layer 2 Broadcasts

  • Every NIC reads the frame, including the router's interface.

Layer 3 Broadcasts

Two types: 1. Directed broadcast to a specific network (e.g., 172.16.255.255 for the 172.16.0.0/16 network). 2. Local broadcast 255.255.255.255 — any network, all hosts.

By default, routers do not forward broadcasts.

Unicast

  • One specific destination IP.
  • All hosts on the LAN see the frame (because Ethernet is broadcast multiaccess), but only the matching NIC accepts it.

Multicast

  • Range: 224.0.0.0 – 239.255.255.255 (Class D).
  • One-to-many: sent to hosts subscribed to a multicast group.
  • Routers DO forward multicast to interfaces with subscribers (unlike broadcasts).
  • Common multicast addresses:
  • 224.0.0.5 — OSPF All Routers
  • 224.0.0.6 — OSPF Designated Routers
  • 224.0.0.9 — RIPv2
  • 224.0.0.10 — EIGRP

📌 Multicast saves CPU on hosts, not bandwidth on the LAN. Every NIC still receives the frame on a broadcast LAN like Ethernet, but non-subscribed hosts discard it at the NIC level instead of bothering the CPU.

💡 No broadcasts in IPv6. IPv6 replaces broadcast functionality with multicast.

Exam Topics Covered - 1.6 Configure and verify IPv4 addressing and subnetting

⚠️ This is THE most important chapter in CCNA Volume 1. Subnetting is the single most-tested skill on the exam. If you can subnet in your head in under 15 seconds, you've already beaten 80% of test-takers. Practice this chapter until it's automatic.

4.1 Why Subnet?

A single Class A, B, or C network address gives you one broadcast domain. Putting all hosts in one giant network is bad because: - Too many broadcasts → congestion (broadcast storms) - One LAN failure affects everyone - No segmentation = no security boundaries - Wasted address space (a Class A has 16+ million hosts!)

Subnetting = taking bits from the host portion of an address and using them to create smaller networks. Trades host capacity for network count.

Benefits of Subnetting

  • Reduced network broadcast traffic
  • Optimized network performance
  • Simplified management (smaller failure domains)
  • Spans large geographical distances (different subnets per site)

4.2 The Three Subnetting Setup Steps

Before you subnet, plan:

  1. Determine number of required network IDs (one per LAN + one per WAN link)
  2. Determine number of required host IDs per subnet (one per host + one per router interface)
  3. Create:
  4. One subnet mask for your network
  5. A unique subnet ID for each segment
  6. A range of valid host IDs for each subnet

4.3 Subnet Masks

A subnet mask is a 32-bit value that tells a device which part of the IP address is the network/subnet portion and which part is the host portion.

  • 1 bits in the mask = network/subnet portion
  • 0 bits in the mask = host portion

📌 Never reduce a mask below its class default (don't make a Class B /8 — and 255.255.255.255 is illegal as a mask, it's a broadcast).

4.6 The ip subnet-zero Command

By default in IOS 12.x and later, this command is enabled. It lets you use the first (0) and last subnets in your network design.

Without ip subnet-zero, you'd lose two subnets to "reserved" status. With it enabled, every subnet is usable.

Router#sh running-config
...
ip subnet-zero

📌 Exam trap: If a router rejects a valid-looking subnet config with Bad mask /XX for address …, the cause is ip subnet-zero is not enabled. The address is in the zero subnet.

⚠️ Read questions carefully — Cisco sometimes specifies "do NOT use ip subnet-zero" or "do not consider the zero subnet valid." This changes your subnet count.

4.7 The Lammle Method — The Big 5 Questions

When given any IP address and mask, answer these in order:

# Question How
1 How many subnets? 2ˣ where x = number of subnet bits (the 1s borrowed)
2 How many hosts per subnet? 2ʸ − 2 where y = number of host bits (the 0s remaining)
3 What are the valid subnets? 256 − mask value = block size. Start at 0 and count up.
4 Broadcast address of each subnet? One less than the next subnet
5 Valid host range? Numbers between subnet and broadcast (exclusive of both)

💡 The block size IS the increment. Once you find it (256 − mask), you can do everything else.

4.9 The Universal Subnetting Process (Step-by-Step)

For any IP + mask, no matter the class:

Step 1: Find the interesting octet

Look at the mask. The interesting octet is the one with a value other than 255 or 0 — that's where subnetting happens.

  • /25 to /30 → fourth octet
  • /17 to /24 → third octet (and possibly fourth for /25-/30 with Class B)
  • /9 to /16 → second octet

Step 2: Find the block size

Block size = 256 − mask value (in the interesting octet)

Step 3: List the subnet boundaries

Start at 0, add the block size repeatedly, stop when you exceed the mask value.

Step 4: Locate the host's subnet

Find the two subnet boundaries the host's IP falls between. The lower one is the subnet.

Step 5: Find the broadcast

The broadcast is one less than the next subnet.

Step 6: List valid hosts

Everything between subnet+1 and broadcast−1 inclusive.

4.13 Class A Subnetting

Same process. With Class A, you have 24 host bits to play with, so any mask /9 through /30 is fair game.

Example: 10.16.3.65 /23

  • 15 subnet bits, 9 host bits
  • Block size in 3rd octet = 256 − 254 = 2
  • 3rd octet subnets: 0, 2, 4, 6 … (counting by 2s)

4.15 Real-World Subnet Selection — Quick Decision Guide

"How many subnets do I need?"

Pick the smallest mask that gives you at least that many. Round UP.

"How many hosts per subnet do I need?"

Pick the largest mask that still gives you at least that many. Use the host count column above.

Worked: "5 subnets, 16 hosts each"

  • For 16+ hosts → need at least 16 hosts/subnet → /28 gives 14 (not enough!) → /27 gives 30 hosts ✅
  • /27 gives 8 subnets — enough for the required 5.
  • Answer: 255.255.255.224 (/27)

Worked: "29 subnets, max hosts"

  • Need ≥ 29 subnets.
  • /27 gives 8 (not enough), /28 gives 16 (no), /29 gives 32 ✅
  • Answer: /29 — but check, Cisco's answer in the book was /21 for Class B asking 29 subnets (different context — for a Class B). Always identify the class first.

The Point-to-Point WAN Rule

Use /30 for any router-to-router serial/WAN link. Exactly 2 usable hosts — no waste. This is a Cisco best practice and a frequent exam answer.

4.16 Common Subnetting Question Patterns

Pattern 1: "What is the subnet address?"

  1. Find block size from mask
  2. Count by block size until you pass the host IP
  3. The previous boundary is the subnet

Pattern 2: "What is the broadcast?"

  1. Find subnet (Pattern 1)
  2. Broadcast = next subnet − 1

Pattern 3: "What is the valid host range?"

  1. Find subnet and broadcast
  2. Range = subnet+1 through broadcast−1

Pattern 4: "How many subnets and hosts?"

  • Subnets: 2^(borrowed bits)
  • Hosts: 2^(remaining host bits) − 2

Pattern 5: "What mask do I need for X subnets / Y hosts?"

Walk the "What Do We Know?" table until both conditions are satisfied.

Pattern 6: "Is this IP a valid host?"

  • If the IP equals the subnet address → ❌ (it's the network ID)
  • If the IP equals the broadcast → ❌
  • Otherwise → ✅

Pattern 7: "What will the router do with this packet?"

  • If the destination is a broadcast address for a subnet → router drops it (routers don't forward broadcasts)

4.17 The 256 Trick — Why This Works

Block size = 256 − mask

This works because: - Each octet is 256 possible values (0–255) - The mask value tells you where to "stop" in that octet - The difference is how big each "step" of the subnet is

Example with /26 (mask = 192): - 256 − 192 = 64 - The mask leaves 64-value chunks in the interesting octet - Subnets jump by 64: 0, 64, 128, 192

💡 You don't even need binary for most questions. The 256 trick + block size = everything.

Common Exam Gotchas from This Chapter

  2. Routers drop packets sent to a broadcast address. Look for the host IP being a broadcast for the subnet.
  3. /30 = 2 hosts, /31 outside CCNA scope, /32 is a host route, not a usable subnet.
  4. 172.16.3.255 can be a valid host on a /23 — don't assume .255 always means broadcast! Check the mask.
  5. 0 and 255 in the fourth octet are valid hosts when subnetting happens above the fourth octet (e.g., Class B with /17 to /23).
  6. Class B /25 has 512 subnets, not 256. The mask uses the third octet's 256 values AND splits each of those in two with the bit in the fourth octet.
  7. When a question says "do not use the zero subnet," you start counting at the first non-zero subnet (e.g., 16 for /28, not 0).
  8. Always count by block size starting at 0 unless told otherwise.
  9. Broadcast = one less than the next subnet. Memorize this — fastest path to the answer.
  10. A /24 used on a Class B is NOT a "Class C mask." It's still a Class B address with 8 bits of subnetting. The class is determined by the FIRST OCTET, not the mask.
  11. Subnet bits start from the left and move right — you can't skip bits. That's why the only valid mask values are 128, 192, 224, 240, 248, 252, 254, 255.
  12. Including the router interface in a host count question — the router's IP eats one host, but it's still counted in the "X hosts per subnet" total.

5.3 Cisco's 4-Step Troubleshooting Method (MEMORIZE)

Scenario: A user complains they can't reach a remote server. Walk through these steps in order:

# Step Command What Passing Confirms What Failing Means
1 Ping loopback ping 127.0.0.1 IP stack is initialized TCP/IP needs to be reinstalled
2 Ping local NIC ping <own IP> NIC and LAN driver are functional NIC problem
3 Ping default gateway ping <router IP> Physical layer LAN works; you can reach the router Problem between host and router (cable, switch, VLAN, gateway config)
4 Ping remote host ping <server IP> End-to-end IP connectivity works Remote network problem — go troubleshoot the destination

After Step 4 Succeeds But User Still Can't Connect

  • IP connectivity is fine — must be a name resolution problem.
  • Check DNS settings on the host.

💡 Memory trick: "Stack → NIC → Gateway → Remote." Or even simpler: "Inside out." Test the host's stack first, then its NIC, then the local network, then the remote network.

📌 Exam pattern: "If pinging the loopback succeeds but pinging the local IP fails, what's wrong?" → NIC is broken. You've ruled out the stack (loopback worked) but can't reach the card.

What Each Step Rules Out

If Step Passes You've Confirmed Working You've Ruled Out
Step 1 (loopback) IP stack TCP/IP installation issue
Step 2 (own IP) NIC + LAN driver NIC failure
Step 3 (gateway) Local physical network Cable, NIC, local switch, gateway reachability
Step 4 (remote) End-to-end IP path Anything except name resolution

5.5 Symptoms vs. Causes — Diagnostic Logic Table

Once you identify which step failed, you can narrow the cause:

Symptom Likely Cause

Can ping loopback, can't ping own IP NIC failure or wrong IP assigned

The "Wrong Gateway" Exam Pattern

Question pattern: "Host A has the wrong default gateway. All other configs are correct. What works?"

Answer: Host A can still talk to other hosts in its own subnet (no router involved) but cannot reach anything outside the subnet, because every packet that needs to leave the subnet goes to the gateway — and the wrong gateway address means those packets go nowhere.

5.6 Applying Subnetting to Troubleshooting

This is where Chapter 4 pays off. Every IP troubleshooting question becomes: 1. Identify the mask (CIDR) 2. Calculate block size 3. Determine each subnet, broadcast, and host range 4. Check whether each device's IP fits in its subnet 5. Spot the misconfigured one — usually a broadcast address assigned as a host

The "Broadcast Assigned as Host" Trap

This is the most common Lammle troubleshooting setup. Look at a network diagram. One device has been assigned the broadcast address of its subnet instead of a valid host. The router will reject it with Bad mask errors, or the host simply can't communicate.

How to spot it: Calculate the broadcast of each subnet, then scan device IPs. If any device IP equals a broadcast — that's your problem.

Worked Example — Lammle Figure 5.2

Network: 192.168.1.0, all segments use /27

  • Mask /27 → block size 32
  • Subnets: 0, 32, 64, 96, 128, 160, 192, 224
  • Sales LAN uses subnet .32 → broadcast = .63 → valid hosts .33–.62
  • Marketing LAN uses subnet .64 → broadcast = .95 → valid hosts .65–.94
  • WAN link uses subnet .96 → broadcast = .127 → valid hosts .97–.126

If the Lab B router's gateway is assigned 192.168.1.63 → that's the broadcast of the Sales subnet. Invalid host. Router will reject it. That's the bug.

Worked Example — Lammle Figure 5.3

Network: /29 throughout

  • Mask /29 → block size 8
  • Sales LAN on .24 subnet → broadcast .31 → hosts .25–.30
  • WAN link on .40 subnet → broadcast .47 → hosts .41–.46
  • Marketing LAN on .80 subnet → broadcast .87 → hosts .81–.86

If ServerB has IP 192.168.x.87 → that's the broadcast of the Marketing subnet. Bug found.

💡 Pattern recognition: Cisco diagrams in troubleshooting questions almost always hide the bug as a broadcast address used as a host. Calculate the broadcast first.

5.7 Assigning IP Addresses Correctly

When asked "assign first usable host" or "assign last usable host," you need to know the exact subnet boundaries.

Worked Example: Server in 192.168.20.24/29

  • /29 = 255.255.255.248, block size 8
  • Subnet = .24, broadcast = .31, valid hosts = .25–.30
  • First usable = .25 (often goes to the router)
  • Last usable = .30 (often goes to a server)

So: - Router gets 192.168.20.25 - Server gets 192.168.20.30 - Both use mask 255.255.255.248 - Server's default gateway = 192.168.20.25 (the router)

Worked Example: Finding a Valid Host for Router 192.168.10.33/27

  • /27 = 255.255.255.224, block size 32
  • Subnet = .32, broadcast = .63, valid hosts = .33–.62
  • Router is on .33 — first usable
  • A new host can be .34 through .62
  • Mask: 255.255.255.224
  • Gateway: 192.168.10.33

Lammle's "Tricky" Example — 172.16.17.0/22

The trap: Most people see 172.16.17.0 and assume it's a network address. It's NOT a subnet boundary with a /22 mask.

  • /22 = 255.255.252.0, block size 4 in the third octet
  • 3rd-octet subnets: 0, 4, 8, 12, 16, 20, 24...
  • Subnet 172.16.16.0 → broadcast 172.16.19.255 → hosts 172.16.16.1 – 172.16.19.254
  • So 172.16.17.0 is a valid host IP, not a network address!

📌 Exam wisdom: Always identify the mask first, then determine subnet boundaries. Never assume an octet of 0 means "network address" without checking the mask.

5.8 The "Choose the Right Mask" Question

Pattern: "I need X subnets, with the largest subnet needing Y hosts. What mask?"

Method

  1. Identify the largest host requirement (any subnet must accommodate at least that many).
  2. Find the smallest host-bit count that gives you ≥ Y hosts (remember 2ⁿ − 2).
  3. Confirm the resulting mask gives you ≥ X subnets.

Worked Example

"5 subnets, Wyoming needs 16 users. What mask?"

  • Need ≥16 hosts/subnet. Check options:
  • /28 → 14 hosts ❌ (not enough)
  • /27 → 30 hosts ✅
  • Need ≥5 subnets. /27 gives 8 subnets ✅
  • Answer: /27 (255.255.255.224)

💡 Why not /28 if 16 = 16? Because 2⁴ − 2 = 14, not 16. You always subtract 2 for the subnet + broadcast addresses.

5.9 Bad Mask Error — The Hidden Cause

When configuring a router interface, if you see:

Bad mask /XX for address X.X.X.X

The two possible causes are: 1. The IP is in the zero subnet AND ip subnet-zero is disabled (rare on modern IOS). 2. The IP is the subnet address itself or the broadcast — not a valid host.

📌 Real-world rule: Cisco IOS will refuse to let you configure a subnet or broadcast address as an interface IP. If you see this error, the IP you typed is one of those reserved addresses.

Real-World Troubleshooting Workflow (Mental Checklist)

When a user calls "the network isn't working":

  1. Identify the scope — One user? Whole office? One application?
  2. Layer 1 check — Cable plugged in? Link lights green?
  3. Step 1 (loopback) — Stack OK?
  4. Check IP config — ipconfig /all. Is there an IP? Is it APIPA (169.254)?
  5. Step 2 (NIC) — NIC alive?
  6. Step 3 (gateway) — Reach the router?

6.1 What Is Cisco IOS?

The Cisco IOS (Internetwork Operating System) is the proprietary kernel that runs on most Cisco routers and current Catalyst switches.

What IOS Is Responsible For

  • Carrying network protocols and functions
  • Connecting high-speed traffic between devices
  • Providing security (access control)
  • Providing scalability (network growth, redundancy)
  • Providing reliability (connectivity to resources)

Quick History

  • First IOS written by William Yeager in 1985.
  • Runs on routers and Catalyst switches (2960, 3560, etc.).

6.3 Boot Sequence (MEMORIZE)

When you power on a Cisco device:

  1. POST (Power-On Self-Test) — hardware check
  2. Load IOS from Flash memory → expanded into RAM
  3. Locate and load startup-config from NVRAM
  4. startup-config is copied to RAM → now called running-config
  5. If no startup-config exists → enter setup mode (interactive dialog)

Memory Types in Cisco Devices

Memory Holds Persistence
ROM Bootstrap, POST, mini-IOS Permanent
Flash IOS image Survives reboot
NVRAM startup-config Survives reboot
RAM (DRAM) running-config, routing tables, ARP cache Lost on reboot

📌 Critical distinction: running-config = RAM (volatile). startup-config = NVRAM (persistent). If you don't save, you lose your changes.

Setup Mode

  • Triggered automatically when no startup-config exists.
  • Can be invoked manually with setup from privileged mode.
  • Press Ctrl+C to abort at any time.
  • Avoid setup mode. Always use the CLI.

Banners

Three types you must know:

Todd(config)#banner motd #

The # is the delimiter — first occurrence starts the message, second occurrence ends it. You can use any character; common choices are #, ^, ~.

6.7 Setting Up SSH (Best Practice — Replaces Telnet)

SSH encrypts traffic; Telnet sends everything in cleartext. Always use SSH in production.

SSH Setup — 7 Steps

  1. Set hostname (required for keypair generation) Router(config)#hostname Todd
  2. Set domain name (required for keypair generation) Todd(config)#ip domain-name Lammle.com
  3. Create local user account Todd(config)#username Todd password Lammle
  4. Generate the RSA keypair Todd(config)#crypto key generate rsa Recommended modulus: 1024 bits or higher (768 minimum for SSHv2).
  5. Enable SSH version 2 (recommended) Todd(config)#ip ssh version 2
  6. Enter VTY config Todd(config)#line vty 0 15
  7. Use local database and allow only SSH Todd(config-line)#login local Todd(config-line)#transport input ssh

⚠️ Never use transport input all — it allows insecure protocols.

📌 To allow both SSH and Telnet (rarely needed): transport input ssh telnet.

💡 Required for SSH: hostname + domain name + username/password + crypto key. Without any of these, SSH won't work.

6.11 Serial Interface Specifics (WAN Links)

DTE vs. DCE

Side Provides Clocking? Typical Role
DTE (Data Terminal Equipment) No Router (in production, plugged into CSU/DSU)
DCE (Data Circuit-terminating Equipment) YES CSU/DSU in production; one router in a lab back-to-back setup
  • By default, Cisco router serial interfaces are DTE.
  • In a lab with back-to-back serial cables, ONE side must be DCE and provide clocking.
  • In production, the CSU/DSU provides clocking → don't set clock rate.

Setting Clock Rate (DCE Side Only)

Router(config-if)#clock rate 1000000

The clock rate is set in bits per second.

📌 New ISR routers auto-detect DCE and set clock rate to 2,000,000 automatically.

Setting Bandwidth

Router(config-if)#bandwidth 1000
  • Default is 1544 Kbps (T1) for serial interfaces.
  • Set in kilobits per second (different from clock rate!).
  • Used by routing protocols like EIGRP and OSPF for metric calculations.
  • RIP ignores bandwidth — it uses hop count.

📌 Clock rate is bps; Bandwidth is Kbps. Don't mix them up.

Identifying DTE vs. DCE

Router#show controllers serial 0/0/0

Output will reveal: V.35 DTE cable or V.35 DCE cable.

6.15 Interface Statistics — Troubleshooting Counters

From show interface output, watch these counters:

Counter What It Means Likely Cause If Incrementing
Input errors Total of all input failures (sum of below) Various — check individual counters
CRC errors Frame failed checksum Interference, bad cable, duplex mismatch
Runts Frames smaller than 64 bytes Collisions
Giants Frames larger than 1518 bytes MTU mismatch, malformed frames
Frame errors Illegal/incomplete frame format Collisions
No buffer Out of receive buffer space Broadcast storm, bad NIC, bad design
Ignored Packets dropped due to full buffers Same as no buffer
Overrun NIC overwhelmed receiving Burst overload
Collisions Half-duplex collisions Expected on half-duplex; bad on full-duplex
Late collisions Collisions after byte 64 Duplex mismatch or cable too long
Output errors Frames couldn't be sent Various send-side problems
Interface resets Interface bounced Link instability

Cisco-Favorite Diagnostic Patterns

Pattern Meaning
CRC + input errors increasing, NO collisions Interference on the cable (EMI), bad cable, or NIC issue
CRC + input errors increasing, WITH collisions Duplex mismatch (one side half, other side full)
Late collisions Duplex mismatch — almost always
No buffer + ignored increasing Broadcast storm on the LAN
Runts + collisions Normal-ish on half-duplex; abnormal on full-duplex

📌 Exam favorite: Cisco shows you a counter dump like the Lammle review question #1. CRCs and input errors are huge, but collisions are 0. Answer: interference, NOT duplex mismatch. (Duplex mismatch would also show collisions or late collisions.)

Duplex Mismatch — The Big One

A duplex mismatch happens when one end is full-duplex and the other is half-duplex.

Symptoms: - Late collisions on the half-duplex side - CRC errors and slow performance - Intermittent connectivity - The link STAYS UP — that's what makes it tricky

Fix: Manually set both ends to the same duplex (preferably full).

Detection: Cisco devices with CDP enabled will log a message:

%CDP-4-DUPLEX_MISMATCH: duplex mismatch discovered on FastEthernet0/2 (not half duplex)

7.1 Internal Components of a Cisco Router/Switch (MEMORIZE)

Component Storage Purpose
Bootstrap ROM Brings up the router; loads the IOS
POST (Power-On Self-Test) ROM Hardware check; identifies present interfaces
ROM Monitor (ROMMON) ROM Manufacturing/test/troubleshooting; password recovery mode
Mini-IOS (RXBOOT / bootloader) ROM Small backup IOS — used if main IOS in flash fails
RAM (DRAM) Volatile Packet buffers, ARP cache, routing tables, running-config, expanded IOS
ROM (Read-Only Memory) Permanent Holds POST, bootstrap, mini-IOS

📌 Exam favorites: - Flash = IOS storage (not NVRAM) - NVRAM = startup-config + config register - Default config register = 0x2102 (load IOS from flash, load config from NVRAM) - ROMMON = the mode you boot into for password recovery - Running-config lives in RAM → lost on reboot if not saved

7.2 The Router/Switch Boot Sequence (MEMORIZE THE ORDER)

1. POST (in ROM) → tests hardware, inventories interfaces
2. Bootstrap (in ROM) → locates and loads IOS
3. IOS loaded from FLASH → expanded into RAM
4. Look in NVRAM for startup-config
5. If found → copy to RAM as running-config; device is operational
6. If NOT found → broadcast for TFTP server with config
7. If TFTP fails → enter Setup mode

Default IOS Loading Order

Flash → TFTP server → ROM (mini-IOS)

📌 Exam point: If flash and TFTP both fail, the router falls back to the mini-IOS in ROM (ROMMON).

7.4 Configuring DHCP on Cisco IOS

DHCP can run on Cisco routers and L3 switches as a server. Required info:

  1. Network ID + subnet mask (the "scope")
  2. Reserved/excluded addresses (for routers, servers, printers, etc.)
  3. Default gateway (router address)
  4. DNS server address(es)
  5. Lease time (optional — default is 24 hours)

Configuration Steps (in order)

Switch(config)#ip dhcp excluded-address 192.168.10.1 192.168.10.10
Switch(config)#ip dhcp pool Sales_Wireless
Switch(dhcp-config)#network 192.168.10.0 255.255.255.0
Switch(dhcp-config)#default-router 192.168.10.1
Switch(dhcp-config)#dns-server 4.4.4.4
Switch(dhcp-config)#lease 3 12 17
Switch(dhcp-config)#option 66 ascii tftp.lammle.com
Command Purpose
ip dhcp excluded-address <start> <end> Reserve IPs (do FIRST!)
ip dhcp pool <name> Create a pool (enters DHCP config mode)
network <net> <mask> The scope
default-router <ip> Gateway given to clients
dns-server <ip> DNS server given to clients
lease <days> <hours> <minutes> Lease duration
option 66 ascii <fqdn> TFTP server for VoIP/auto-install

📌 Critical order: Exclude addresses FIRST, before creating the pool. Once the network statement is configured, DHCP starts responding immediately — and may hand out IPs you wanted reserved.

DHCP Relay (ip helper-address) — Exam Favorite

If clients are on a different subnet than the DHCP server, the router would normally drop their DHCP DISCOVER broadcasts. Use ip helper-address to forward them.

Router(config)#interface fa0/0
Router(config-if)#ip helper-address 10.10.10.254
  • Configure on the interface closest to the clients (the one receiving the broadcasts).
  • The ip helper-address is the IP of the actual DHCP server.

📌 ip helper-address forwards more than just DHCP — by default it relays 8 UDP services (DHCP/BOOTP, TFTP, DNS, time, NetBIOS name/datagram, TACACS). Be aware of unintended side effects in production.

CDP is a Cisco-proprietary Layer 2 protocol that lets Cisco devices discover and share info about directly connected Cisco neighbors.

Attribute Value

7.12 Network Time Protocol (NTP)

NTP synchronizes clocks across network devices using UDP port 123. Critical for: - Accurate timestamps in syslog messages - Certificate validation (TLS/SSL) - Kerberos authentication - Forensic analysis and event correlation

NTP Configuration

As an NTP Client

Router(config)#ntp server 192.168.1.1

As an NTP Server (Master)

Router(config)#ntp master 3       ! stratum 3

Authenticated NTP (Best Practice)

Router(config)#ntp authenticate
Router(config)#ntp authentication-key 1 md5 cisco
Router(config)#ntp trusted-key 1
Router(config)#ntp server 192.168.1.1 key 1

NTP Stratum

  • Stratum 0 = atomic clock or GPS (the reference)
  • Stratum 1 = directly connected to stratum 0
  • Stratum 2 = synced from stratum 1
  • ... up to Stratum 15 (max)
  • Stratum 16 = unsynchronized

📌 Lower stratum = closer to the reference clock = more accurate.

Verifying NTP

Command Shows

How Severity Filtering Works

When you set a logging level, you get THAT level AND ALL LOWER (more severe) levels.

  • logging trap 3 → sends levels 0, 1, 2, AND 3 (emergencies, alerts, critical, errors)
  • logging trap 5 → sends 0-5 (everything except informational and debug)
  • logging trap 7 → sends everything

📌 Exam trap: "logging trap 3 — what gets sent?" → Errors (3), Critical (2), Alerts (1), Emergencies (0). Notice it does NOT include warnings (4) — that's a level lower in severity (higher number).

Common Exam Gotchas from This Chapter

  1. Default config register = 0x2102. This loads the IOS from flash and the config from NVRAM.
  2. IOS lives in Flash, NOT NVRAM. NVRAM holds the startup-config.
  3. Running-config = RAM (volatile). Must copy run start to save.
  4. show cdp neighbors does NOT show IP addresses. You need show cdp neighbors detail or show cdp entry * for IPs.
  5. CDP is Cisco-only, Layer 2, enabled by default. LLDP is the standard equivalent, disabled by default.
  6. CDP only sees directly connected neighbors. Cannot cross routers.
  7. ip helper-address forwards 8 UDP services, not just DHCP.
  8. DHCP conflicts must be fixed manually. Server doesn't auto-resolve.
  9. exclude addresses BEFORE creating the DHCP pool, or they may get assigned before you finish.
  10. terminal monitor required to see console output (including debug) in a Telnet/SSH session.
  11. tracert is Windows; traceroute is Cisco/Linux/macOS. They are not interchangeable.
  12. debug all can crash a router. Always use specific debugs and check show processes cpu first.
  13. no ip domain-lookup stops the router from trying to DNS-resolve typos (a major real-world annoyance).
  14. NTP master command: ntp master <stratum>. NTP client command: ntp server <ip>. The keyword server configures a client — counterintuitive but correct.
  15. Syslog severity levels: 0=Emergency, 7=Debug. Lower number = more severe.
  16. logging trap N sends levels 0 through N (that level and all more severe). Don't get tripped up by the directionality.
  17. TFTP uses UDP port 69. Syslog uses UDP 514. NTP uses UDP 123. Memorize these.
  18. Ctrl+Shift+6 then X suspends Telnet without disconnecting.
  19. Restored config via TFTP brings up interfaces SHUT DOWN by default. Must no shutdown each one.
  20. copy tftp run is a MERGE, not a replace. For replace, use configure replace.

8.1 The Configuration Register

Every Cisco router has a 16-bit software register stored in NVRAM that controls how the router boots.

Default Value: 0x2102

The 0x prefix means hexadecimal. 2102 breaks down as:

Hex Digit Binary Meaning
2 0010 Bit 13 ON — boot default ROM if network boot fails
1 0001 Bit 8 ON — Break key disabled
0 0000 Nothing
2 0010 Bit 1 ON — Boot field = 2 (boot from flash)

💡 Easier way to think of 0x2102: Boot from flash, use the startup-config from NVRAM, disable the Break key during boot.

Configuration Register Bit Map (FYI — don't memorize all of these)

Bit Hex Description
0-3 0x0000-0x000F Boot field (see next table)
6 0x0040 Ignore NVRAM contents (used for password recovery!)
7 0x0080 OEM bit enabled
8 0x0100 Break disabled
10 0x0400 IP broadcast with all zeros
5, 11-12 0x0800-0x1000 Console line speed
13 0x2000 Boot default ROM software if network boot fails
14 0x4000 IP broadcasts do not have network numbers
15 0x8000 Enable diagnostic messages and ignore NVRAM

The Boot Field (Bits 0-3) — MEMORIZE

The last hex digit of the config register determines where the IOS boots from:

Boot Field Config Register Boot Source Prompt
0x0 0x2100 ROM Monitor — manual boot with b rommon>
0x1 0x2101 Mini-IOS (ROM) — boot from ROM IOS Router(boot)>
0x2 - 0xF 0x2102 - 0x210F Use NVRAM boot system commands Normal Router>

📌 Three values you must know: - 0x2102 = default; load IOS from flash, use NVRAM config - 0x2100 = boot to ROMMON - 0x2142 = password recovery! Ignore NVRAM (skip startup-config)

8.2 Checking and Changing the Configuration Register

View Current Setting

Router#show version
[output cut]
Configuration register is 0x2102

The config register is always the LAST LINE of show version output.

Change the Register

Router(config)#config-register 0x2142
Router(config)#do show version
[output cut]
Configuration register is 0x2102 (will be 0x2142 at next reload)

⚠️ Critical: The change takes effect on the next reload, not immediately. After changing, you must reload for it to apply.

📌 Exam trap: If you saved the config and the router boots into setup mode, your config register is probably wrong (maybe 0x2142 left over from a password recovery).

8.3 Password Recovery Procedure (MEMORIZE THE SEQUENCE)

Why It Works

Setting bit 6 (0x2142) tells the router to ignore the startup-config in NVRAM. The router boots clean, and you can then load the startup-config into RAM, change the password, and save it.

The 8 Steps (in exact order)

1. Boot the router and IMMEDIATELY press Break (Ctrl+Break)
   → drops you into ROMMON: rommon 1>

2. At rommon> prompt, change the config register:
   rommon 1> confreg 0x2142

3. Reset / reboot the router:
   rommon 2> reset

4. Router boots WITHOUT the startup-config (you're in clean mode)
   Skip the setup dialog (type "no" or Ctrl+C)

5. Enter privileged mode and COPY startup-config to running-config:
   Router> enable
   Router# copy startup-config running-config
   (Now you have the config in RAM, but you're already logged in)

6. Change the password(s):
   Router# config t
   Router(config)# enable secret NewPassword

7. CRITICAL: Restore the config register to 0x2102:
   Router(config)# config-register 0x2102
   Router(config)# end

8. Save and reload:
   Router# copy running-config startup-config
   Router# reload

📌 Exam pattern: "What config register value do you use for password recovery?" → 0x2142.

📌 Critical mistake to avoid: If you forget step 7 (restoring 0x2102), the router will boot without its config every time you reload — and the next admin will think your config is gone.

💡 Why copy startup-config to running-config? Because skipping NVRAM gives you a blank router. To preserve all interfaces, ACLs, routing, etc., you pull the saved config into RAM, then change the password without losing anything else.

Switch Password Recovery (Slightly Different)

Cisco switches don't have a config register. Instead: 1. Power off the switch. 2. Hold the Mode button while powering on. 3. Release when LED turns amber/green. 4. At switch: prompt, run: switch: flash_init switch: load_helper switch: dir flash: switch: rename flash:config.text flash:config.old switch: boot 5. Skip setup, then rename flash:config.old flash:config.text, copy flash:config.text running-config. 6. Change passwords, save.

8.4 Boot System Commands

By default, the router boots the first IOS image found in flash. You can override this with boot system commands.

Configuration Order (Fallback Chain)

Router(config)#boot system flash c2800nm-advsecurityk9-mz.151-4.M6.bin
Router(config)#boot system tftp c2800nm-advsecurityk9-mz.151-4.M6.bin 1.1.1.2
Router(config)#boot system rom

This tells the router: 1. Try flash first with that specific filename 2. Fallback to TFTP if flash fails (6 attempts to reach the TFTP server) 3. Final fallback to ROM (mini-IOS) if both fail

Available boot system Sources

Option Use
flash Boot from flash with a specific filename
tftp Boot from a TFTP server
ftp Boot from FTP
rcp Boot from rcp
rom Boot the mini-IOS from ROM

📌 Production best practice: Set explicit boot system flash <filename> commands so the router always loads the exact IOS you want — never relies on flash ordering.

8.7 IOS Licensing (ISR G2 Routers, IOS 15.0+)

Pre-15.0, IOS feature sets came as separate image files (one per feature combo — 8 total). Starting with 15.0, Cisco uses universal images.

Universal Image Concept

  • ONE image file per router model contains ALL feature sets.
  • Features are locked by default; you unlock them with licenses.
  • Includes a built-in 60-day evaluation period for premium features.

📌 IP Base is the foundation. The other three are add-ons.

9.1 Routing Protocols vs. Routed Protocols (Critical Distinction)

Concept Examples Purpose
Routed protocol IP, IPv6 The protocol that carries user data. Assigned to interfaces.
Routing protocol RIP, RIPv2, OSPF, EIGRP, BGP The protocol routers use to dynamically share routing info.

💡 One-line rule: Routed protocols carry the data; routing protocols share the map.

What Routers Need to Route Effectively

  1. Destination address
  2. Neighbor routers to learn remote networks from
  3. Possible routes to all remote networks
  4. Best route to each remote network (chosen by metric)
  5. Verification mechanism to keep routes current

9.3 Administrative Distance (AD) — Trustworthiness

When multiple routing sources tell the router about the same network, the router picks the one with the lowest AD (most trusted).

Source AD

External BGP (eBGP) 20
Internal EIGRP 90

External EIGRP 170

💡 Memory hook (the big four): Connected 0, Static 1, EIGRP 90, OSPF 110, RIP 120. The rest are edge cases.

9.4 Forwarding Decisions — How Routers Choose (Exam Topic 3.2)

When forwarding a packet, the router picks the best route using three tiebreakers in order:

Decision Order (MEMORIZE)

  1. Longest prefix match — most-specific network wins
  2. Administrative distance (if multiple sources matched at the same prefix length)
  3. Metric (if multiple routes from the same source matched at the same prefix length)

Example — Longest Match Rule

Given routing table:

S   10.0.0.0/8     [1/0] via 1.1.1.1
S   10.10.0.0/16   [1/0] via 2.2.2.2
S   10.10.10.0/24  [1/0] via 3.3.3.3

Packet destined for 10.10.10.30: - Matches all three routes - But longest match wins → 10.10.10.0/24 is most specific - Forwarded via 3.3.3.3

📌 Critical: Longest match is checked first, before AD or metric. Don't get this order wrong.

9.5 Routing Metrics by Protocol

Routing Protocol Metric
RIP / RIPv2 Hop count (max 15)
EIGRP Composite (bandwidth + delay default; load, reliability, MTU optional)
OSPF Cost (based on bandwidth — lower = better)
IS-IS Cost
BGP Path attributes (AS path, local preference, MED, etc.)

📌 Lower metric = better route (within the same routing protocol). Hop count, cost, composite — all "smaller is better."

9.6 The IP Routing Process — Step by Step

When Host A pings Host B on a different subnet:

Sending Side (Host A → its default gateway)

  1. ICMP creates echo request payload (the alphabet)
  2. IP wraps it in a packet with src/dst IPs and Protocol = 0x01 (ICMP)
  3. IP sees destination is on a remote network → sends to default gateway
  4. ARP cache checked for default gateway's MAC
  5. If not cached, ARP broadcast finds the gateway's MAC
  6. Data Link layer frames it with Host A's MAC (src) and gateway's MAC (dst)
  7. Physical layer transmits the bits

At the Router

  1. Router receives bits → builds frame → runs CRC
  2. Checks destination MAC — it's the router's own interface
  3. Strips the frame → reads Ether-Type (0x0800 = IP)
  4. Hands the packet to IP
  5. IP looks up the destination network in the routing table
  6. If no route → drops packet, sends ICMP "network unreachable" back to Host A
  7. If route found → switches packet to the exit interface's buffer
  8. ARP cache checked for next-hop MAC (or ARP request)
  9. New frame built with router's exit-interface MAC (src) and next-hop MAC (dst)
  10. Frame transmitted

📌 Critical concept: MAC addresses are always LOCAL. They never traverse a router. Each router strips the incoming frame and builds a new one with new src/dst MAC addresses for the next hop. The IP addresses stay the same end-to-end (unless NAT is involved).

Receiving Side (Host B)

  1. Host B receives frame, runs CRC, checks dest MAC → match
  2. Strips frame → hands packet to IP
  3. IP checks dest IP → matches its own IP
  4. Reads Protocol field → 0x01 = ICMP → hands payload to ICMP
  5. ICMP recognizes echo request → builds echo reply
  6. Process reverses for the return trip

Common Failure Patterns

Error Message Where the Failure Happened
Request timed out Unknown error — usually packet lost on return path
Destination host unreachable Sending host has no route (no default gateway)
Destination network unreachable A router along the path has no route in its table

💡 Real-world troubleshooting insight (from Lammle): When ping fails, most people assume the packet didn't reach the destination. Wrong. It often arrived fine — but the return path failed. A request timed out means "I sent it, didn't get a reply" — could be either direction.

9.7 Cisco Router Internal Forwarding (Process Switching, Fast Switching, CEF)

Three packet-forwarding methods, each faster than the last:

Method How It Works When Used
Process Switching Every packet → full routing table lookup → CPU heavy Legacy / fallback
Fast Switching First packet uses process switching, builds a cache; subsequent packets use cache Older IOS
CEF (Cisco Express Forwarding) Pre-built FIB (Forwarding Information Base) and adjacency table; change-triggered, not packet-triggered Default on all modern routers

Verifying Switching Method

Router#show ip interface fa0/0

📌 CEF is the modern default. Exam question "what's the default packet-forwarding method on Cisco routers?" → CEF.

💡 CEF builds two tables: FIB (mirror of the routing table optimized for hardware lookup) and adjacency table (next-hop MAC addresses). Together they enable wire-speed forwarding.

9.9 Default Routes (a Special Kind of Static)

A default route matches everything — used when no other route matches.

Default Route Syntax

Router(config)#ip route 0.0.0.0 0.0.0.0 <next-hop>

0.0.0.0/0 means "any network, any host." It's the least specific route possible, so it's only used when nothing else matches (longest match rule).

Example

LA(config)#ip route 0.0.0.0 0.0.0.0 10.10.10.5

"For anything I don't know how to reach, send to 10.10.10.5."

What It Looks Like in the Table

S*   0.0.0.0/0 [1/0] via 10.10.10.5

The * marks it as a candidate default route, and you'll see:

Gateway of last resort is 10.10.10.5 to network 0.0.0.0

📌 Exam point: Gateway of last resort = the default route. Used when nothing else matches.

Use Case

Common on stub routers (e.g., a branch with one WAN link to HQ). Instead of telling the branch about every internal network, you just give it a default route pointing to HQ.

9.10 Static Route Variants (All Tested)

1. Network Route (Standard Static)

Routes to an entire subnet.

ip route 192.168.1.0 255.255.255.0 10.1.1.1

2. Default Route

Matches everything not otherwise matched.

ip route 0.0.0.0 0.0.0.0 10.1.1.1

3. Host Route

Route to a single specific host (uses /32 mask).

ip route 192.168.1.100 255.255.255.255 10.1.1.1

💡 Useful for special-case servers or routing a specific monitoring station through a different path.

4. Floating Static Route

A backup static route with higher AD than the primary route.

ip route 192.168.1.0 255.255.255.0 10.1.1.1            ! primary, AD=1
ip route 192.168.1.0 255.255.255.0 10.2.2.1 150        ! backup, AD=150

📌 The "150" makes this a floating static — it's hidden in the routing table until the primary route fails, then it "floats" to the top.

💡 Common pairing: Primary route via OSPF (AD 110) + floating static via WAN backup (AD 150 or higher). When OSPF dies, the static takes over.

9.13 Dynamic Routing — RIP (the Educational One)

⚠️ RIP is mostly historical. Lammle covers it because it's the simplest dynamic routing protocol — perfect for teaching concepts. Don't use it in production. OSPF (Ch 10) and EIGRP (Ch 11) are what you'll actually use.

Types of Dynamic Routing Protocols

Type How It Works Examples
Distance Vector Each router shares its routing table with neighbors. Picks routes by distance (hops). RIP, RIPv2, IGRP, EIGRP*
Link State Each router shares link info with everyone; each builds a full topology and runs SPF OSPF, IS-IS
Hybrid / Advanced Distance Vector Combines features of both EIGRP
Path Vector Tracks paths/AS hops; supports policy BGP

💡 EIGRP is technically a hybrid / advanced distance vector protocol but is often categorized as distance vector.

Distance Vector Characteristics

  • Periodic updates of the entire routing table
  • Updates sent only to directly connected neighbors
  • "Routing by rumor" — believes whatever neighbors say
  • Slow convergence
  • Susceptible to routing loops

Loop Prevention Techniques

  • Split horizon — don't send a route back out the interface it came in on
  • Route poisoning — advertise a failed route with infinite metric (RIP: hop count 16)
  • Hold-down timers — ignore updates about a route for a period after it fails
  • Triggered updates — send immediate updates on topology change (not waiting for periodic interval)

Feature RIPv1 RIPv2
Type Distance vector Distance vector

Configuring RIPv2

Router(config)#router rip
Router(config-router)#version 2
Router(config-router)#no auto-summary
Router(config-router)#network 192.168.10.0
Router(config-router)#network 10.0.0.0

📌 The network command takes a CLASSFUL address. For 192.168.10.0/24, you type network 192.168.10.0 (no mask). RIP figures out which interfaces to enable based on the classful match.

📌 no auto-summary is critical — without it, RIPv2 will summarize subnets to their classful boundary, breaking discontiguous networks.

Verifying RIP

Command Shows
show ip route rip Just RIP routes
show ip protocols All routing protocols, their networks, AD, timers

Why RIP Is Mostly Dead

  • 15-hop maximum makes it unusable for large networks
  • Full table updates every 30 seconds wastes bandwidth
  • Slow convergence (up to 240 seconds for failures to propagate fully)
  • No bandwidth awareness — picks routes purely by hop count even over a slow link

Common Exam Gotchas from This Chapter

  1. Forwarding decision order: Longest match first, then AD, then metric. Don't reverse this.
  2. L (local) routes are /32 routes for the router's own interface IPs — appeared in IOS 15.
  3. Gateway of last resort = default route. Marked with * in routing table.
  4. AD 0 = Connected, 1 = Static, 110 = OSPF, 120 = RIP. The big four.
  5. AD 255 = unreachable — route NOT installed.
  6. MAC addresses are local; they change at every router hop. IPs stay the same end-to-end (unless NAT).
  7. request timed out = unknown error (often return-path failure). destination unreachable = a router has no route.
  8. CEF is the default packet-forwarding method on modern Cisco routers.
  9. Static routes have AD = 1, which is more trusted than any dynamic protocol.
  10. Floating static routes use a higher AD (e.g., 150) to act as backup for a dynamic route.
  11. Default route syntax: ip route 0.0.0.0 0.0.0.0 <next-hop>. IPv6: ipv6 route ::/0 <next-hop>.
  12. Host route uses /32 mask. ip route 1.1.1.1 255.255.255.255 ....
  13. ipv6 unicast-routing is required to enable IPv6 routing — globally configured, not per-interface.
  14. RIPv1 = classful, broadcasts (255.255.255.255). RIPv2 = classless, multicasts (224.0.0.9).
  15. RIP max hops = 15. Hop 16 = "infinity" / unreachable. RIP works on networks with diameter ≤ 15 routers.
  16. network command in RIP/EIGRP takes a classful address — no subnet mask. The protocol figures out interfaces.
  17. no auto-summary required in RIPv2/EIGRP for discontiguous networks to work properly.
  18. RIP update interval = 30 sec. Hold-down = 180 sec. Flush = 240 sec.
  19. A static route to an exit interface (vs. a next-hop IP) is treated as "directly connected" by some IOS versions — has AD 0, not 1. Lammle's syntax (ip route ... Serial0/0/0) is valid; the next-hop IP form is more common.
  20. DHCP server, client, and relay can all run on a single router — but on different interfaces.

Determining the Router ID (RID) — IN ORDER

OSPF picks the RID at startup using this priority: 1. router-id command explicitly set under OSPF process (highest priority) 2. Highest IP address on any active loopback interface 3. Highest IP address on any active physical interface

📌 Critical: The RID is determined at OSPF startup and does NOT change automatically when interfaces come/go. To force a new RID, you must either clear the OSPF process with clear ip ospf process or reload the router.

💡 Best practice: Always explicitly set the RID with router-id <IP> — gives you predictable behavior and avoids surprises when interfaces go up/down.

10.3 OSPF Operation — How It Works

Three OSPF Tables (MEMORIZE)

Table Contents
Neighbor table All OSPF neighbors discovered via Hello packets
Topology table (LSDB) All LSAs from the area — identical on all routers in same area
Routing table Best paths chosen by the SPF algorithm

The OSPF Process

1. Router starts OSPF → allocates memory for neighbor/topology tables
2. Hello packets sent on OSPF-enabled interfaces (every 10 sec on broadcast/p2p)
3. Routers exchange Hellos → become NEIGHBORS
4. On broadcast networks → elect DR and BDR
5. Routers exchange LSAs → build the topology table (LSDB)
6. Dijkstra's SPF algorithm runs → builds shortest-path tree
7. Best paths installed into the routing table
8. Steady state: Hellos maintain neighborships; LSAs flooded only on change

Hello Protocol Details

Network Type Hello Interval Dead Interval
Broadcast (Ethernet) 10 sec 40 sec
Point-to-point 10 sec 40 sec
Non-broadcast (NBMA) 30 sec 120 sec
Point-to-multipoint 30 sec 120 sec

📌 Dead interval = 4 × Hello interval (Cisco default). If no Hello received within the dead interval → neighbor declared dead.

What Hello Packets Carry (Must Match for Adjacency)

  • Area ID (must match!)
  • Authentication password (must match if used)
  • Hello and Dead intervals (must match!)
  • Stub area flag (must match if used)
  • Subnet mask on common link (must match!)
  • Router ID
  • DR/BDR election priority

📌 Exam favorite: If two OSPF routers won't form an adjacency, check (in order): Area ID → Hello/Dead timers → Authentication → Subnet mask → MTU.

10.4 OSPF Neighbor States (Adjacency Process)

When two routers form an adjacency, they transition through these states:

State What Happens
Down No Hello received yet
Init Hello received but my RID not in their Hello
2-Way Mutual visibility — I see them and they see me. On multi-access networks, DR/BDR election happens here.
ExStart Master/slave relationship established for DBD exchange
Exchange DBD (Database Description) packets exchanged — summary of LSDB
Loading LSRs (Link State Requests) sent to fill gaps in LSDB
Full LSDBs are fully synchronized — routers are fully adjacent

💡 Memory hook (Lammle's mnemonic): "Down Init 2-Way ExStart Exchange Loading Full" — Does It Take Every Engineer Long Fairly.

📌 Exam point: Full state means fully adjacent. Two routers in 2-Way are neighbors but NOT adjacent (this is normal between two DROTHERs).

Why 2-Way Is Sometimes Final

On broadcast networks, DROTHERs do NOT become fully adjacent with each other — they only become fully adjacent with the DR and BDR. This is the optimization the DR provides.

10.5 OSPF Areas (Hierarchical Design)

OSPF requires a hierarchical area design with a backbone area.

Key Rules

  • Area 0 is the backbone area — REQUIRED.
  • All other areas must connect to area 0.
  • Routers within the same area have identical LSDBs.
  • Areas reduce LSDB size and CPU load (you don't flood all LSAs everywhere).

Router Types

Router Where It Lives
Internal Router All interfaces in one (non-backbone) area
Backbone Router At least one interface in area 0
Area Border Router (ABR) Connects two or more areas — must have one interface in area 0
Autonomous System Boundary Router (ASBR) Connects OSPF to another routing domain (e.g., redistributes EIGRP or BGP into OSPF)

📌 An ABR has interfaces in multiple areas AND area 0. An ASBR redistributes routes from outside OSPF.

Single-Area OSPF (CCNA Focus)

All routers in area 0. Simpler config, smaller networks. Multi-area OSPF is CCNP-level.

10.6 LSA Flooding

When a topology change occurs: 1. Router detects the change (link up/down). 2. Generates new LSA → multicasts to 224.0.0.5 (or to DR at 224.0.0.6 on broadcast networks). 3. All routers in the area receive the LSA, update their LSDB. 4. Each router re-runs SPF and updates the routing table.

LSA Update Multicast Addresses

Network Type Multicast Used
All OSPF routers 224.0.0.5 (AllSPFRouters)
DRs (from DROTHERs) 224.0.0.6 (AllDRouters)

📌 On broadcast networks: DROTHERs send LSAs to 224.0.0.6 (only the DR/BDR listen). The DR then floods to 224.0.0.5 so all DROTHERs get it. This optimization is the whole reason DR exists.

10.7 SPF Tree Calculation and Metrics

OSPF uses Dijkstra's algorithm to build a shortest-path tree from each router's perspective, with itself as the root.

OSPF Cost Formula

Cost = 10^8 / Bandwidth (in bps)

= 100,000,000 / interface bandwidth in bps

Interface Speed Cost
10 Mbps (Ethernet) 10
100 Mbps (Fast Ethernet) 1
1 Gbps (Gigabit) 1 (saturates the formula)
10 Gbps 1 (saturates the formula)

⚠️ Real-world issue: Because the default reference bandwidth is 100 Mbps, all interfaces 100 Mbps or faster get the same cost (1). On modern Gigabit/10G networks, this makes OSPF unable to distinguish path speeds.

Fix: Adjust the Reference Bandwidth

Router(config-router)#auto-cost reference-bandwidth 10000

This sets the reference to 10 Gbps. Must be done on every router in the OSPF domain for consistency.

Manually Set Cost

Router(config-if)#ip ospf cost 100

10.8 DR and BDR Election (Broadcast Networks Only)

On a broadcast network (Ethernet), OSPF elects a Designated Router (DR) and Backup Designated Router (BDR) to minimize LSA flooding overhead.

Why DR/BDR Exists

Without DR, every router would have to form full adjacency with every other router → n*(n-1)/2 adjacencies. With DR/BDR, every router forms adjacency only with the DR and BDR → 2n adjacencies.

DR/BDR Election Order (in order)

  1. Highest OSPF interface priority (default 1; 0 = ineligible)
  2. Highest Router ID (tiebreaker)

Set OSPF Priority

Router(config-if)#ip ospf priority 100
  • Default: 1
  • Range: 0–255
  • Priority 0 = the router will never be DR/BDR

Key DR/BDR Behavior

  • Election is NOT preemptive — even if a higher-priority router shows up later, it does NOT take over from the current DR.
  • To force a re-election, restart OSPF or shut/no shut the interface.
  • DR/BDR is per-segment, not per-router. A router can be DR on one segment and DROTHER on another.

📌 Exam favorite scenario: Three routers come online simultaneously. Which becomes DR? → Highest priority wins; tie broken by highest RID.

Basic OSPF Configuration

The Process ID

  • Range: 1–65535
  • Locally significant only — does NOT have to match between neighbors
  • Use to differentiate multiple OSPF processes on one router (rare)

📌 Exam point: Different routers can use different process IDs and STILL form neighbors. The process ID is local.

Wildcard Masks (Important!)

The network command uses a wildcard mask, which is the inverse of a subnet mask:

Subnet Mask Wildcard Mask
255.0.0.0 (/8) 0.255.255.255
255.255.0.0 (/16) 0.0.255.255

💡 Quick math: Wildcard = 255.255.255.255 - subnet mask. Or: 0 = "must match," 1 = "don't care."

What the Wildcard Does

network 10.0.0.0 0.255.255.255 area 0
  • Match any interface with an IP in the 10.0.0.0/8 range.
  • Place those interfaces in area 0.

You can also match a single interface specifically:

network 192.168.1.1 0.0.0.0 area 0

"Match exactly 192.168.1.1, put it in area 0."

Modern Alternative — Interface-Level Configuration

Instead of network statements, you can enable OSPF directly on an interface:

Router(config)#router ospf 1
Router(config)#interface GigabitEthernet0/0
Router(config-if)#ip ospf 1 area 0

This is cleaner — modern best practice.

Passive Interface

Stops OSPF Hellos from being sent on an interface (still advertises the network).

Router(config-router)#passive-interface GigabitEthernet0/0

Use case: A LAN interface where there are no other OSPF routers — silence the Hellos to save CPU and security (don't broadcast OSPF presence).

10.10 OSPF Loopback Interfaces (Best Practice)

A loopback is a virtual interface that's always up. Critical for OSPF because: 1. Provides a stable RID — physical interface IPs can change. 2. Always up — won't bounce.

Configuring a Loopback

Router(config)#interface Loopback 0
Router(config-if)#ip address 1.1.1.1 255.255.255.255

📌 Best practice: Use /32 masks on loopbacks to avoid wasting address space. Each router gets a unique loopback IP (1.1.1.1, 2.2.2.2, etc.) used as its RID.

Effect on RID

When a loopback is configured BEFORE OSPF starts, OSPF uses its IP as the RID. If OSPF was already running, you must clear the process:

Router#clear ip ospf process

11.1 EIGRP Overview

Enhanced Interior Gateway Routing Protocol (EIGRP) was Cisco-proprietary until 2013, when Cisco released it as an open standard (RFC 7868). It's a classless, advanced distance-vector protocol that combines characteristics of both distance-vector and link-state protocols.

Key Characteristics (MEMORIZE)

Feature EIGRP
Type Advanced distance-vector (hybrid)
Algorithm DUAL (Diffusing Update Algorithm)
Metric Composite (bandwidth + delay default)
Open standard? Yes (RFC 7868, formerly Cisco-proprietary)
Classless / VLSM Yes
Hop count 100 default, 255 max (not used as metric — caps AS size only)
Convergence Very fast (often faster than OSPF)

EIGRP Features

  • Supports IP and IPv6 via protocol-dependent modules (PDMs)
  • Supports VLSM/CIDR and discontiguous networks
  • No broadcasts — uses multicast 224.0.0.10
  • Bounded updates — sends changes only to affected routers
  • Reliable Transport Protocol (RTP) — its own reliability layer
  • DUAL — pre-computed backup paths (feasible successors) enable instant failover

📌 The "hybrid" / "advanced distance vector" label: EIGRP sends distance-vector-style updates (with metrics, not link-state info), but it ALSO maintains a topology of neighbors' best paths and uses Hellos for neighbor discovery — link-state-like behaviors.

11.2 EIGRP Tables

EIGRP maintains three tables (just like OSPF, but with different semantics):

Table Contents
Neighbor table All directly-connected EIGRP routers that have exchanged Hellos
Topology table All routes from all neighbors — both successors AND feasible successors
Routing table Best paths (successors) installed into the IP forwarding table

💡 Key difference from OSPF: EIGRP topology tables on different routers do NOT have to be identical — each router only knows what its neighbors told it. OSPF LSDBs in the same area MUST be identical.

11.4 EIGRP Neighbor Discovery and Adjacency

How Neighbors Form

  1. EIGRP sends Hello packets to multicast 224.0.0.10 every 5 seconds (default on LAN/p2p).
  2. Routers exchange Hellos → become neighbors.
  3. Once neighbors form, routers exchange full routing tables once (using update packets).
  4. Steady state: only changes get propagated (bounded updates).

Hello and Hold Timers

Link Type Hello Interval Hold Time (3× Hello)
Broadcast/LAN, fast WAN (≥1.544 Mbps) 5 sec 15 sec
Slow WAN (<1.544 Mbps, NBMA) 60 sec 180 sec

📌 EIGRP Hold = 3 × Hello (not 4× like OSPF).

Conditions for Neighbor Adjacency (MUST MATCH)

Requirement Why
Same AS number EIGRP routers in different ASs do NOT share routes
K-values match Metric calculation must be consistent
Authentication matches (if used) Security
Primary IPs in same subnet Hellos must be exchangeable

⚠️ Unlike OSPF, Hello/Hold intervals do NOT need to match between EIGRP neighbors. They can be different (the hold timer just tells the neighbor how long to wait before declaring you dead). This is a subtle but important difference from OSPF.

📌 Exam favorite scenario: Two routers won't form EIGRP adjacency. Check: AS number mismatch, K-value mismatch, wrong subnet.

11.5 EIGRP Packet Types

Packet Type Purpose Reliable?
Hello Discover/maintain neighbors No (multicast)
Update Route info on change Yes (reliable multicast or unicast)
Query "Hey, do you have a path to X?" — sent when going active Yes
Reply Response to Query Yes
ACK Acknowledge a reliable packet No (unicast)

💡 Reliable Transport Protocol (RTP) provides EIGRP with its own ACK/retransmit mechanism, since IP and multicast are unreliable. RTP is built into EIGRP — not the real-time RTP for VoIP.

11.6 The DUAL Algorithm — How Successors Work

DUAL (Diffusing Update Algorithm) is what makes EIGRP fast. It maintains backup paths pre-computed, so failover is instant.

Concept

        SF        ← AD=2  (SF's cost to 10.0.0.0)
       /
Corp -- cost 5 to reach SF
       \
        NY        ← AD=10 (NY's cost to 10.0.0.0)

Corp's FD through SF = 5 + 2 = 7  ← SUCCESSOR
Corp's FD through NY = 5 + 10 = 15

Feasibility condition for NY to be FS:
  NY's AD (10) < Corp's current successor FD (7)?
  10 < 7?  NO → NY is NOT a feasible successor!

📌 The Feasibility Condition (FC): Neighbor's AD must be LESS than the current successor's FD for that neighbor to qualify as a feasible successor.

This guarantees loop-free backup paths.

Successor vs. Feasible Successor

Type Where Stored Use
Successor Topology table + Routing table Active best route
Feasible Successor (FS) Topology table only Backup; ready to install if successor fails

💡 Why this matters: When a successor goes down, EIGRP instantly promotes the FS — no recalculation, no queries needed. Convergence is sub-second.

When There's No FS Available

  • Route goes ACTIVE (entering recalculation)
  • Router sends Query packets to all neighbors
  • Waits for Replies
  • If no reply within 180 seconds (default) → Stuck-In-Active (SIA)
  • SIA → neighbor relationship reset

11.7 EIGRP Metric — The Composite Formula

EIGRP's metric is a composite value based on five variables, controlled by five K-values:

K-Value Represents Default
K1 Bandwidth 1 (ON)
K2 Load 0 (OFF)
K3 Delay 1 (ON)
K4 Reliability 0 (OFF)
K5 MTU 0 (OFF)

📌 By default, only K1 (bandwidth) and K3 (delay) are used.

Default Simplified Formula

Metric = 256 × (10^7 / lowest bandwidth in path in Kbps + delay sum / 10)

Where: - Bandwidth = lowest bandwidth along the path, in Kbps - Delay = sum of all delays along the path, in microseconds / 10

💡 You don't need to memorize the formula for the CCNA. You just need to know that bandwidth and delay matter, load and reliability don't (by default).

K-values Must Match

EIGRP neighbors will not form an adjacency if their K-values differ. Don't change K-values unless you know what you're doing on every router in the AS.

📌 Best practice: Leave K-values at default. Tune metric by changing interface bandwidth or delay, NOT K-values.

Tuning Interface Bandwidth (for EIGRP/OSPF metric, NOT throughput!)

Router(config-if)#bandwidth 64        ! 64 Kbps (used by routing protocols only)

⚠️ The bandwidth command does NOT change actual interface speed. It only changes the value used by EIGRP, OSPF, etc. for metric calculation.

11.8 Maximum Paths and Hop Count

Equal-Cost Load Balancing

By default, EIGRP installs up to 4 equal-cost paths to the same destination, doing per-packet or per-flow load balancing.

Router(config-router)#maximum-paths 6        ! support up to 6 paths

Max value: 32.

Hop Count

  • Default: 100
  • Maximum: 255

Hop count is NOT used in metric calculation. It's only a sanity check — EIGRP packets exceeding hop count are dropped to prevent runaway loops.

Router(config-router)#metric maximum-hops 200

11.9 Unequal-Cost Load Balancing (EIGRP's Unique Trick)

EIGRP can load-balance over paths of different costs using the variance command.

How Variance Works

  • Variance is a multiplier (default 1 = equal-cost only).
  • A feasible successor whose FD is ≤ variance × successor's FD will also be installed in the routing table.

Example

Successor FD = 100
FS FD = 250
Variance = 3 → installs paths up to FD 300

Both routes installed; traffic split proportionally to inverse of metric.

Configuration

Router(config-router)#variance 3

📌 Only feasible successors qualify for unequal-cost load balancing. Non-FS paths can't be used (loop risk).

💡 Real-world note: This is unique to EIGRP — OSPF and RIP can only equal-cost load balance.

11.10 Split Horizon

To prevent routing loops, EIGRP uses split horizon: don't advertise a route back out the interface you learned it on.

Where Split Horizon Causes Problems

  • Frame Relay hub-and-spoke (NBMA)
  • Multipoint subinterfaces

If you need spokes to learn each other's routes via the hub, you must disable split horizon on the hub:

Router(config-if)#no ip split-horizon eigrp <AS>

📌 Default: split horizon is ENABLED on all EIGRP-enabled interfaces.

11.11 Configuring EIGRP

Basic EIGRP Configuration (Classic)

Router(config)#router eigrp 10
Router(config-router)#network 10.0.0.0
Router(config-router)#network 172.16.0.0
Router(config-router)#no auto-summary

Process Number = AS Number

  • Range: 1–65535
  • Must MATCH between routers that want to form neighbors (unlike OSPF process IDs)

Network Command — Classful or Wildcard

Classful (no mask):

Router(config-router)#network 10.0.0.0

Enables EIGRP on ALL interfaces whose IPs fall within the classful 10.0.0.0/8.

Wildcard mask (more precise):

Router(config-router)#network 192.168.1.0 0.0.0.255

Enables EIGRP only on interfaces matching the wildcard.

💡 Wildcard form is preferred for precision, especially when multiple subnets share a classful network.

Disabling Auto-Summary

Router(config-router)#no auto-summary

⚠️ EIGRP auto-summary is ENABLED by default in older IOS (and re-enabled in some 15.x versions for backward compatibility). It summarizes subnets to their classful boundary at AS boundaries → breaks discontiguous networks.

Always run no auto-summary unless you have a specific reason.

Modern EIGRP Named Mode (15.x+)

Router(config)#router eigrp TODD
Router(config-router)#address-family ipv4 unicast autonomous-system 10
Router(config-router-af)#network 10.0.0.0 0.255.255.255

Cleaner, hierarchical config. CCNA mostly tests classic mode.

Manual Summarization (Per Interface)

Router(config-if)#ip summary-address eigrp 10 192.168.0.0 255.255.0.0

Passive Interface

Stops Hello packets on the interface (but still advertises the network):

Router(config-router)#passive-interface GigabitEthernet0/0

📌 Difference from OSPF: EIGRP passive-interface completely disables EIGRP on that interface — neighbors can NOT form (no Hellos sent OR received). OSPF passive-interface just stops Hellos (it'll still advertise).

12.1 Why Switching?

Layer 2 switching breaks a large collision domain into many smaller ones — one per switch port. Compared to old hub-based networks:

Hubs Switches
One collision domain shared by all ports Per-port collision domain
Half-duplex only Full-duplex per port
Single broadcast domain Still single broadcast domain (until VLANs)
No filtering — every port sees every frame Selective forwarding based on MAC
Layer 1 only (signal repeater) Layer 2 (reads frames)

Layer 2 Switching Advantages

  • Hardware-based bridging via ASICs (Application-Specific Integrated Circuits)
  • Wire-speed forwarding
  • Low latency
  • Low cost

💡 A switch is fundamentally a multiport bridge with ASIC acceleration. Same job, vastly more efficient.

📌 Layer 2 switches and bridges are faster than routers because they only look at Layer 2 headers, not Layer 3.

12.2 The Three Switch Functions at Layer 2 (MEMORIZE)

Function What Happens
1. Address Learning Builds the MAC address table from source addresses of incoming frames
2. Forward/Filter Decisions Decides whether to forward, flood, or filter based on destination MAC
3. Loop Avoidance Uses STP (Spanning Tree Protocol) to prevent Layer 2 loops

12.3 Address Learning — How the MAC Table Is Built

When a frame arrives, the switch reads the source MAC and records: - The MAC address - The port it came in on - A timestamp

The MAC table (also called the CAM table for Content Addressable Memory, or filter table) maps MAC addresses → switch ports.

Learning Process Step by Step

  1. Switch boots → MAC table is empty.
  2. A frame arrives on a port.
  3. Switch records (source MAC, ingress port, timestamp) in the MAC table.
  4. Switch decides what to do with the frame (forward/flood) based on destination MAC.

MAC Aging (Exam Topic 1.13.a)

Entries are removed from the MAC table if not refreshed within the aging time (default 300 seconds = 5 minutes on Cisco switches).

📌 Why aging matters: A device moves to a different port (e.g., laptop changes location). The old MAC entry needs to expire so the switch can re-learn the new location.

12.4 Forward/Filter Decisions (Exam Topic 1.13.b/c)

When a frame's destination MAC is checked:

Destination MAC Type Switch Action Term
Known unicast (in MAC table) Forward out the specific port Frame switching / forwarding
Unknown unicast (NOT in table) Send out all ports except the source Unicast flooding
Broadcast (ff:ff:ff:ff:ff:ff) Flood out all ports except source Broadcast flooding
Multicast (e.g., 01:00:5e:...) Flood by default (unless IGMP snooping enabled) Multicast flooding
Destination MAC = source port's known MAC Drop / filter (no need to send back) Filtering

The Forward/Filter Logic

1. Frame arrives on port X
2. Read destination MAC
3. Look it up in MAC table
   a. Found, and points to port X → DROP (filtering)
   b. Found, points to different port Y → FORWARD out port Y only
   c. Not found → FLOOD out all ports except X
4. If broadcast/multicast → FLOOD

📌 "Frame flooding" (exam topic 1.13.c) = unknown unicast or broadcast/multicast frames sent out all ports except source.

💡 Filtering is when the switch doesn't forward a frame because the destination is on the same port as the source. This is rare but important to know.

12.5 Port Security (Exam Topic 5.7)

Port security restricts which MAC addresses can use a switch port — preventing unauthorized devices from connecting.

Use Cases

  • A receptionist's PC port shouldn't suddenly have an unknown laptop on it.
  • Stop someone unplugging an IP phone and plugging in a rogue device.
  • Limit MAC flooding attacks (CAM table overflow).

Configuring Port Security — Step by Step

Switch(config)#interface fa0/3
Switch(config-if)#switchport mode access                ! port security requires access mode
Switch(config-if)#switchport port-security              ! enable port security
Switch(config-if)#switchport port-security maximum 1    ! max MACs allowed (default 1)
Switch(config-if)#switchport port-security mac-address sticky    ! learn and save MAC
Switch(config-if)#switchport port-security violation shutdown    ! action on violation

Important: Port Security Requirements

Requirement Reason
Must be access mode Won't work on trunk or dynamic ports
Must be enabled with switchport port-security Required (and order matters!)

📌 Common error: Tried to enable port security on a port that's still dynamic (default mode). Fix: switchport mode access first.

Sticky MAC

With mac-address sticky, the switch learns the first MAC dynamically and saves it to the running-config. After copy run start, the MAC persists across reboots.

💡 Sticky vs. Static: - Sticky = auto-learn the first MAC, then lock to it - Static = manually type the MAC: switchport port-security mac-address 0001.0001.aaaa

Default is 1. Useful in a phone + PC scenario where the PC plugs through the phone: - 1 MAC for the phone - 1 MAC for the PC

12.6 Layer 2 Loop Avoidance — STP Overview

If you connect switches in a loop (intentionally for redundancy or accidentally), the following bad things happen:

Problems Without STP

  1. Broadcast storms — broadcasts loop forever, growing exponentially
  2. MAC table instability — same MAC seen on multiple ports, table flips constantly
  3. Multiple frame copies — receivers get the same frame multiple times → application confusion

💡 Why this is catastrophic: Ethernet frames have no TTL (unlike IP packets). A looped frame circulates forever until the switch crashes.

Spanning Tree Protocol (STP) — The Solution

STP (IEEE 802.1D) automatically detects loops and blocks redundant links to break them — while keeping the link available as backup.

STP Key Concepts (Light Coverage — Detail Comes Later)

Concept Brief Description
Root bridge One switch elected as the "anchor" — has the lowest Bridge ID
Bridge ID Combination of Priority (default 32768) + MAC address
BPDU Bridge Protocol Data Unit — STP's hello message (sent every 2 sec)
Root port (RP) Port on a non-root switch with lowest cost to root
Designated port (DP) Best port on each segment to forward toward root
Blocked port Redundant port — stops loops; can still receive BPDUs
Forwarding state Normal data-passing state
Convergence Time for STP to stabilize (~30-50 sec on STP, ~6 sec on RSTP)

Port Cost in STP (Default)

Link Speed STP Cost

12.9 Layer 2 Security Features (Brief Intro)

Beyond port security, Cisco offers two more L2 security features (Exam Topic 5.7):

DHCP Snooping

Protects against rogue DHCP servers (attacker hands out malicious IPs/gateways).

  • Designates trusted/untrusted ports.
  • Trusted ports allow DHCP server responses (Offer, ACK).
  • Untrusted ports drop these responses.
  • Builds a DHCP binding database (MAC → IP → port).
Switch(config)#ip dhcp snooping
Switch(config)#ip dhcp snooping vlan 10
Switch(config)#interface fa0/24
Switch(config-if)#ip dhcp snooping trust          ! uplink to real DHCP server

Dynamic ARP Inspection (DAI)

Protects against ARP spoofing / poisoning (attacker impersonates the gateway).

  • Inspects every ARP packet against the DHCP snooping binding database.
  • Drops ARPs where MAC ↔ IP doesn't match.
Switch(config)#ip arp inspection vlan 10
Switch(config)#interface fa0/24
Switch(config-if)#ip arp inspection trust

📌 DAI depends on DHCP snooping — DAI uses the snooping binding database to validate ARPs.

💡 Security ladder: Port security (Layer 2 MAC restriction) → DHCP snooping (rogue DHCP server) → DAI (ARP poisoning) → IP Source Guard (IP spoofing).

13.1 What Is a VLAN?

A Virtual LAN (VLAN) is a logical grouping of network users and resources connected to administratively defined ports on a switch.

The Core Concept

  • A VLAN = its own broadcast domain + its own subnet
  • Multiple VLANs on one switch = multiple broadcast domains on one physical box
  • Hosts in different VLANs CANNOT communicate without a router (or L3 switch)
  • A single VLAN can span multiple switches via trunk links

Without VLANs

  • One large flat L2 network = one giant broadcast domain
  • All hosts hear all broadcasts → wasted bandwidth, security risk
  • No segmentation between departments / security zones

With VLANs

  • Logical segmentation independent of physical location
  • Each VLAN = its own broadcast domain
  • Users in VLAN 10 (Sales) can be on multiple floors / buildings
  • Communication between VLANs requires a router or L3 switch

13.2 Why Use VLANs? (Three Big Reasons)

1. Broadcast Control

Without VLANs, every broadcast goes to every host. With VLANs, broadcasts stay within the VLAN.

2. Security

  • Hosts in different VLANs can't communicate by default.
  • Sensitive resources (servers, management) go in restricted VLANs.
  • Inter-VLAN traffic forced through a router/L3 switch where ACLs apply.

3. Flexibility and Scalability

  • Move a user to a new VLAN without rewiring.
  • Add new departments without redesigning the physical network.
  • VLANs span buildings via trunks.

13.4 Trunk Links and Frame Tagging

When a VLAN spans multiple switches, frames need to carry their VLAN identity across the inter-switch link. This is frame tagging.

Two Types of Switch Ports

Port Type Purpose Carries
Access port Connects to an end device (PC, phone, printer) One VLAN untagged
Trunk port Connects to another switch or router Multiple VLANs (tagged with VLAN ID)

What Frame Tagging Does

On a trunk: 1. Frame enters from VLAN X. 2. Trunk adds a VLAN tag = X. 3. Frame travels across the trunk. 4. Receiving switch reads the tag, removes it, sends frame to VLAN X on its end.

13.5 The Two VLAN Tagging Methods

Method Type Notes
ISL (Inter-Switch Link) Cisco proprietary (DEAD) Encapsulates entire frame; old; not on modern Cisco switches
IEEE 802.1Q (dot1q) Open standard Inserts 4-byte tag into existing frame; the modern standard

IEEE 802.1Q — The One That Matters (Exam Topic 2.2.b)

802.1Q inserts a 4-byte tag into the Ethernet frame between the source MAC and the EtherType fields:

[Dest MAC] [Src MAC] [802.1Q Tag (4 bytes)] [EtherType] [Data] [FCS]

The 4-byte tag contains: - TPID (Tag Protocol Identifier) = 0x8100 (identifies the frame as tagged) - PCP (Priority Code Point) = 3 bits for 802.1p QoS - DEI (Drop Eligible Indicator) = 1 bit - VID (VLAN ID) = 12 bits → range 0–4095 (with 0 and 4095 reserved)

📌 802.1Q recalculates the FCS because the frame structure changed. The receiving switch removes the tag and recalculates again.

💡 Why 4094 max VLANs? Because 12 bits = 4096 values, minus VLAN 0 and VLAN 4095 (both reserved).

ISL — Historical Note

  • Cisco-only, deprecated since the mid-2000s.
  • Encapsulates the entire frame (adds 26-byte header + 4-byte FCS).
  • Will not appear on any modern Cisco switch — but CCNA exam may still test the concept.

13.6 The Native VLAN (Exam Topic 2.2.c)

On a trunk link, the native VLAN is the one VLAN whose frames are sent UNTAGGED across the trunk.

Default Native VLAN: VLAN 1

By default, both ends of an 802.1Q trunk send VLAN 1 traffic untagged.

Why Native VLAN Exists

Backward compatibility with legacy devices that don't understand VLAN tags. When a tagged frame arrives at a port that doesn't speak 802.1Q, it would be dropped. The native VLAN solution lets one VLAN's frames pass without tags so legacy devices can still use it.

Native VLAN Must Match on Both Ends

If switch A has native VLAN 1 and switch B has native VLAN 99 on the same trunk: - Traffic from switch A's VLAN 1 arrives untagged - Switch B sees untagged traffic and assigns it to VLAN 99 → VLAN leaking

CDP will detect this and log a %CDP-4-NATIVE_VLAN_MISMATCH message.

📌 Security best practice: Change the native VLAN from 1 to an unused VLAN (e.g., VLAN 999). This prevents VLAN hopping attacks where attackers craft double-tagged frames to escape their VLAN.

Change the Native VLAN

Switch(config)#interface fa0/1
Switch(config-if)#switchport trunk native vlan 999

⚠️ Both ends of the trunk must agree on the native VLAN.

13.10 Inter-VLAN Routing — Three Methods

By default, hosts in different VLANs CANNOT talk to each other. To enable inter-VLAN communication, you need a routing function:

1. Per-Interface Router One physical router port per VLAN Legacy / small / not scalable
2. Router-on-a-Stick (ROAS) One router connected via a single trunk; routes between subinterfaces Mid-size / classic CCNA

13.11 Router-on-a-Stick (ROAS)

A router connected to a switch via a single trunk. The router has subinterfaces — one per VLAN — each with its own IP (gateway for that VLAN).

Topology

   [PC]VLAN10 --+
   [PC]VLAN20 --+--[Switch]==trunk==[Router fa0/0]
                                          ├─ fa0/0.10 (gw for VLAN 10)
                                          ├─ fa0/0.20 (gw for VLAN 20)
                                          └─ fa0/0.50 (gw for VLAN 50)

Router Configuration

Router(config)#interface fa0/0
Router(config-if)#no ip address
Router(config-if)#no shutdown
!
Router(config)#interface fa0/0.10
Router(config-subif)#encapsulation dot1q 10
Router(config-subif)#ip address 192.168.10.1 255.255.255.0
!
Router(config)#interface fa0/0.20
Router(config-subif)#encapsulation dot1q 20
Router(config-subif)#ip address 192.168.20.1 255.255.255.0
!
Router(config)#interface fa0/0.50
Router(config-subif)#encapsulation dot1q 50
Router(config-subif)#ip address 192.168.50.1 255.255.255.0

Switch Side

Switch(config)#interface fa0/15
Switch(config-if)#switchport mode trunk

Native VLAN Handling on ROAS

For the native VLAN, you need to add the native keyword:

Router(config)#interface fa0/0.1
Router(config-subif)#encapsulation dot1q 1 native
Router(config-subif)#ip address 192.168.1.1 255.255.255.0

📌 Exam point: Subinterface number doesn't have to match the VLAN, but it's best practice to make them the same (e.g., fa0/0.10 for VLAN 10) for clarity.

13.12 Layer 3 Switch (SVIs) — Modern Inter-VLAN Routing

A multilayer / Layer 3 switch can route between VLANs internally — at wire speed — using Switched Virtual Interfaces (SVIs).

SVI = "interface vlan X"

An SVI is a logical Layer 3 interface for a VLAN.

Configuration

Switch(config)#ip routing                              ! enable routing!
!
Switch(config)#vlan 10
Switch(config-vlan)#name Sales
Switch(config)#vlan 20
Switch(config-vlan)#name Marketing
!

Switch(config-if)#ip address 192.168.10.1 255.255.255.0

Common Exam Gotchas from This Chapter

  1. VLAN 1 is the default and can't be deleted. All ports start in VLAN 1.
  2. VLAN range 1–1005 = normal, 1006–4094 = extended. The exam focuses on normal range.
  3. 802.1Q tag = 4 bytes. ISL header = 26 bytes (rarely seen now).
  4. 802.1Q EtherType (TPID) = 0x8100. Identifies the frame as tagged.
  5. 802.1Q VLAN ID field = 12 bits, range 1–4094.
  6. Native VLAN = untagged VLAN on a trunk. Default is VLAN 1.
  7. Native VLAN must match on both ends of a trunk or CDP will log a mismatch (%CDP-4-NATIVE_VLAN_MISMATCH).
  8. Change the native VLAN to an unused VLAN for security (prevents VLAN hopping).
  9. DTP: auto + auto = access (no trunk). Both must be at least desirable for a trunk to form.
  10. switchport nonegotiate disables DTP — best practice for security.
  11. Default allowed VLANs on a trunk = ALL. Restrict with switchport trunk allowed vlan.
  12. switchport trunk allowed vlan 30 REPLACES the list. Use add to append.
  13. Voice VLAN is configured with switchport voice vlan X on an access port. PC = data VLAN, phone = voice VLAN — both share the port.
  14. Router-on-a-stick subinterface number doesn't have to match the VLAN — but it's best practice.
  15. encapsulation dot1q 1 native for the native VLAN's subinterface (without native, the router expects tags for that VLAN).
  16. L3 switch requires ip routing at global config — without it, no routing happens.
  17. SVI = interface vlan X — Layer 3 logical interface for a VLAN.
  18. L2 switch needs ip default-gateway for management traffic; L3 switch doesn't (it routes itself).
  19. Hosts in different VLANs cannot communicate without a router or L3 switch.
  20. Trunk ports can carry MANY VLANs, access ports carry exactly ONE data VLAN (+ optionally one voice VLAN).
  21. VLAN 1002–1005 are legacy (Token Ring/FDDI) and CANNOT be deleted.
  22. A "no switchport" command on an L3 switch port converts it to a routed port (like a real router interface).
  23. Two access ports on different VLANs cannot communicate even if on the same switch.
  24. show interfaces trunk shows native VLAN, encapsulation, allowed/active VLANs.

14.1 What Is a VPN?

A Virtual Private Network (VPN) is a secure, encrypted "tunnel" carrying private network traffic across a public network (typically the Internet).

Why VPNs Exist

  • Connect remote sites securely (site-to-site)
  • Let remote workers access the corporate network (remote access)
  • Save money — leasing dedicated WAN lines is expensive; the Internet is everywhere
  • Encrypt sensitive traffic in transit

Two Main VPN Categories (Exam Topic 5.5)

Type Use Case Endpoints
Site-to-Site VPN Connect entire offices/networks together Router to router, firewall to firewall
Remote Access VPN Individual users connect to corporate network User's PC/phone ↔ corporate gateway

📌 Exam point: Site-to-site = networks; Remote access = users.

14.2 Benefits of VPNs

Benefit Description
Security Encryption protects data in transit
Cost savings Use cheap Internet links instead of expensive leased lines
Scalability Add new sites/users easily
Compatibility Works over any IP transport

14.3 Enterprise- and Provider-Managed VPNs

Type Description

Site-to-site VPN (IPsec tunnel) Two corporate edges (routers/firewalls) connected over the Internet

14.4 IPsec — The Workhorse of VPN Encryption

IPsec is a suite of protocols that provides authentication, encryption, and integrity for IP traffic.

IPsec Goals (CIA Triad Applied)

Goal Provided By
Confidentiality (privacy) Encryption
Integrity (no tampering) Hashing (HMAC)
Authentication (who sent it) Digital signatures, pre-shared keys
Anti-replay Sequence numbers

IPsec Security Protocols

Protocol Provides Encrypts? IP Protocol #
AH (Authentication Header) Auth + integrity NO 51
ESP (Encapsulating Security Payload) Auth + integrity + encryption YES 50

📌 Exam point: - AH = no encryption. Only authenticates and ensures integrity. - ESP = encryption + authentication + integrity. This is what's used in production. Pretty much nobody runs AH alone today.

IPsec Modes

Mode What's Encrypted Use Case
Transport mode Just the payload (original IP header preserved) Host-to-host (rare)
Tunnel mode Entire original packet (new outer IP header added) Site-to-site VPNs (most common)

💡 Tunnel mode is the default for site-to-site VPNs because it hides the internal IP topology.

AES 128 / 192 / 256-bit Strong Modern standard

Asymmetric Encryption (Key Pair)

  • RSA — used for authentication and key exchange (signing, not bulk encryption)
  • Diffie-Hellman (DH) — secure key exchange algorithm (the two endpoints agree on a shared secret without sending it across the wire)

Algorithm Output Size Status

14.6 GRE Tunnels

GRE (Generic Routing Encapsulation) is a Cisco-developed tunneling protocol that encapsulates any Layer 3 protocol inside an IP packet.

Key Facts

  • Cisco-developed, now open standard (RFC 2784)
  • IP protocol 47
  • Stateless — no flow control or reliability
  • No encryption by default (that's where IPsec comes in)
  • Supports multicast and routing protocols through the tunnel
  • Easy to configure

Why GRE Matters for VPNs

IPsec alone cannot carry multicast traffic — which means it can't carry routing protocols like OSPF or EIGRP that use multicast. The fix: wrap the routing protocol in a GRE tunnel, then encrypt the GRE tunnel with IPsec → GRE-over-IPsec.

When to Use GRE

  • You need to run a routing protocol across a VPN
  • You need to carry non-IP traffic (rare)
  • You need multicast through a tunnel

Configuring a GRE Tunnel (Both Sides)

Site A

RouterA(config)#interface tunnel 0
RouterA(config-if)#ip address 10.10.10.1 255.255.255.252
RouterA(config-if)#tunnel source 200.1.1.1                ! local public IP
RouterA(config-if)#tunnel destination 200.2.2.1            ! remote public IP
RouterA(config-if)#tunnel mode gre ip                       ! default

Site B

RouterB(config)#interface tunnel 0
RouterB(config-if)#ip address 10.10.10.2 255.255.255.252
RouterB(config-if)#tunnel source 200.2.2.1
RouterB(config-if)#tunnel destination 200.1.1.1
RouterB(config-if)#tunnel mode gre ip

How It Works

  1. Tunnel source and destination are the public/Internet-facing IPs of the two routers.
  2. The tunnel interface itself has a separate IP (the "inside" of the tunnel).
  3. Traffic routed into the tunnel gets a new GRE + IP header with src/dst = the tunnel source/destination.

Verify GRE

RouterA#show ip interface brief
RouterA#show interfaces tunnel 0
RouterA#show ip route                          ! tunnel destination must be reachable!

GRE Gotcha — Recursive Routing

If you advertise the tunnel's source/destination IP through the tunnel itself, the router gets confused and shuts down the tunnel with:

%TUN-5-RECURDOWN: Tunnel0 temporarily disabled due to recursive routing

Fix: Make sure the tunnel destination is reachable via the physical/underlay network, NOT through the tunnel.

📌 Exam point: GRE supports routing protocols and multicast; IPsec alone does not. GRE provides no encryption.

14.7 GRE over IPsec — The Combo

For modern site-to-site VPNs that need both routing protocols AND encryption:

[OSPF/EIGRP traffic]
       ↓
[wrapped in GRE]
       ↓
[encrypted by IPsec]
       ↓
[sent over the Internet]

The combination is sometimes called "crypto map"-based GRE-over-IPsec, but the modern equivalent is IPsec VTI.

14.8 Cisco DMVPN (Dynamic Multipoint VPN)

DMVPN is Cisco-proprietary, designed for hub-and-spoke topologies where spokes need to dynamically build tunnels to each other.

Key Concepts

  • One central hub + many spokes
  • Spokes register with the hub
  • When two spokes need to talk, they build a direct tunnel on demand (no traffic through the hub)
  • Uses mGRE (multipoint GRE), NHRP (Next Hop Resolution Protocol), and IPsec

Benefits

  • Massive scalability — no need to configure each spoke-to-spoke tunnel manually
  • Spokes can have dynamic IPs (e.g., DHCP from ISP)
  • Built-in support for routing protocols

📌 DMVPN is mostly CCNP territory — CCNA just needs to know it exists and is a Cisco-proprietary multi-site VPN.

14.9 IPsec VTI (Virtual Tunnel Interface)

IPsec VTI uses a logical tunnel interface to wrap IPsec. Simpler than crypto maps, supports routing protocols natively.

Router(config)#interface tunnel 0
Router(config-if)#ip address 10.10.10.1 255.255.255.252
Router(config-if)#tunnel source 200.1.1.1
Router(config-if)#tunnel destination 200.2.2.1
Router(config-if)#tunnel mode ipsec ipv4               ! IPsec VTI mode
Router(config-if)#tunnel protection ipsec profile MY-IPSEC-PROFILE

IPsec VTI Advantages

  • Clean config — no crypto maps to maintain
  • Routing protocols (OSPF, EIGRP, BGP) work natively
  • Can apply QoS, ACLs to the tunnel interface like any other interface

💡 Modern best practice for site-to-site: IPsec VTI or DMVPN (for many spokes). Old-school crypto maps are dying out.

15.2 AI Performance Categories (Two Big Types — MEMORIZE)

The biggest, most important distinction in AI is between narrow (predictive) and generalized/generative.

Narrow AI (a.k.a. Weak AI / Predictive AI)

  • Designed to do ONE SPECIFIC TASK extremely well
  • Cannot generalize to other domains
  • Examples: spam filters, Siri, recommendation engines, image classification
  • This is virtually all AI in production today (2026)

Generalized AI (a.k.a. Strong AI / AGI)

  • Hypothetical AI that matches general human intelligence across any domain
  • Doesn't yet exist in real systems
  • Goal of research labs (OpenAI, DeepMind, Anthropic)

Super-Intelligent AI

  • Hypothetical AI that surpasses human intelligence in all domains
  • Pure science fiction at this point (the "Skynet" scenario)
  • Heavy ethical debate

📌 Exam point: "Narrow AI" = task-specific. "Generalized AI" = human-like across any task. "Super-intelligent AI" = beyond human. Currently, everything in production is narrow AI.

15.3 AI Functional Categories (Cognitive Hierarchy)

A different way to classify AI by its cognitive capabilities:

Category Description Example
Reactive Machines No memory; reacts only to current input IBM Deep Blue (chess); old chatbots
Limited-Memory AI Uses recent past experiences to make decisions Self-driving cars; most modern ML systems
Theory-of-Mind AI (Future) Understands emotions, beliefs, intentions Doesn't exist yet
Self-Aware AI (Future / hypothetical) Has consciousness Doesn't exist; debated whether possible

💡 Today's reality: Almost everything you use is limited-memory AI. Modern LLMs (like ChatGPT) are limited-memory AI — they remember the conversation context but have no true understanding.

15.4 AI Architectures (How AI Is Built)

Three foundational AI architectures:

Rule-Based Systems

How they work: Explicit "if-then" rules written by humans.

Strengths Weaknesses
Predictable, transparent Rigid — can't handle novel situations
Easy to debug ("why did it do that?") Requires expert knowledge to build
Fast Doesn't scale to complex domains

Example: A traditional firewall rulebase. "If src=X and dst=Y and port=Z, drop."

Decision Trees

How they work: Branching tree of binary questions leading to a classification.

Strengths Weaknesses
Easy to visualize and explain Can overfit
Fast Doesn't handle complex relationships well
Works with limited data Sensitive to small data changes

Example: "Is the email from a known sender? Yes → trust; No → check spam score." Used in spam filters historically.

Neural Networks (the big one)

How they work: Layers of artificial "neurons" loosely modeled on the brain. Each neuron weights inputs, applies a function, and passes the result onward. Trained by feeding it data and adjusting weights.

Strengths Weaknesses
Handles enormous complexity Requires HUGE training data
Discovers patterns humans miss "Black box" — hard to explain decisions
Powers modern AI (LLMs, computer vision, speech) Expensive to train; high compute needs

Example: ChatGPT, image recognition, voice assistants. All modern generative AI is based on neural networks.

15.6 How Machines Learn — Three ML Approaches

Supervised Learning

  • Trained on labeled data ("this is a cat" / "this is not a cat")
  • Model learns input → output mapping
  • Use cases: Spam detection, fraud detection, image classification, medical diagnosis
Strengths Weaknesses
High accuracy on familiar data Need massive labeled datasets (expensive!)
Predictable performance Can't handle truly novel input types

Unsupervised Learning

  • Trained on unlabeled data
  • Finds patterns/structure on its own
  • Use cases: Customer segmentation, anomaly detection, recommendation engines
Strengths Weaknesses
Works with cheap unlabeled data Output may be hard to interpret
Discovers hidden patterns Less predictable accuracy

Reinforcement Learning (briefly)

  • Learns by trial and error with rewards/penalties
  • Use cases: Game-playing AI, robotics, autonomous vehicles, AI agents

📌 Exam point: Supervised = labeled data, Unsupervised = unlabeled. Reinforcement = trial and error. Memorize this trio.

Predictive vs. Generative AI (Exam Topic 6.4)

Type Purpose Example
Predictive AI Predicts outcomes based on input data Fraud detection ("is this transaction suspicious?"); network anomaly detection ("is this traffic abnormal?")
Generative AI Creates new content — text, images, audio, code ChatGPT (text), DALL-E (images), GitHub Copilot (code)

💡 The simplest distinction: - Predictive AI tells you what WILL happen - Generative AI MAKES something new

📌 Exam topic 6.4 explicitly distinguishes these. Memorize the difference.

15.7 Generative AI and Large Language Models (LLMs)

What's an LLM?

A Large Language Model is a neural network trained on massive amounts of text to predict the next word given previous context. Scaling that up → ChatGPT.

Hallucinations (CRITICAL Concept)

Hallucination = when an LLM confidently produces incorrect information that looks plausible.

⚠️ LLMs do NOT "know" facts — they predict the most-likely next word. When they don't have the right answer, they invent one that sounds reasonable.

Example of LLM Hallucination (from Lammle)

Ask an LLM: "Give me 4 /29 subnets out of the 192.168.0.0/24 network."

A naive LLM might confidently produce subnets that are wrong (overlapping, outside the range, etc.) without realizing it. You CANNOT trust LLM output for technical work without verification.

📌 Exam point and real-world rule: LLMs hallucinate. Always verify the output of an AI tool, especially for configurations, subnets, security policies, or anything involving math/precision.

Data Sovereignty

When you submit your data to a cloud-based AI (ChatGPT, etc.), it may be: - Stored on the provider's servers - Used to train future models - Subject to the provider's country's laws (US, China, EU, etc.)

⚠️ For corporate networking work: Never paste confidential configs, IPs, passwords, or proprietary diagrams into public LLMs. Use enterprise instances (Microsoft 365 Copilot, OpenAI Enterprise, on-prem Llama) instead.

15.9 Strategies for Using AI Effectively

Prompt Engineering

Prompt engineering = crafting your input to the LLM to get better results.

Key principles: 1. Be specific — vague prompts get vague answers 2. Provide context — "I'm a Cisco network engineer working on ..." 3. Define the format — "Output as a markdown table" 4. Use examples — show the format you want 5. Iterate — refine the prompt based on the response

Good vs. Bad Prompts

Bad: "Make me a config."

Good: "Generate a Cisco IOS configuration for a Layer 3 switch with three VLANs (Sales=10, Engineering=20, Voice=50), corresponding SVI IPs (10.10.10.1/24, 10.10.20.1/24, 10.10.50.1/24), enabled routing, an uplink trunk on Gi0/24 to a core switch, and SSH access on the management VLAN."

Retrieval-Augmented Generation (RAG)

RAG = an LLM with access to a specific knowledge base at query time. Instead of relying only on training data, the LLM looks up authoritative info first.

Why it matters: Reduces hallucinations dramatically. Enterprise AI deployments use RAG to ensure the LLM answers from approved corporate documents, not general internet data.

💡 Real-world example: A Cisco support chatbot using RAG retrieves real Cisco documentation when answering, instead of guessing. This is rapidly becoming standard.

Real-World Wrap-Up — AI/ML in Your Future SOC Role

Your SOC analyst career is going to be heavily AI-influenced. Here's what you'll actually encounter:

Where You'll See AI/ML

  1. SIEM correlation engines (Splunk, Sentinel, QRadar) use ML to find suspicious patterns in millions of events.

Skills That Will Set You Apart

  • Understanding what an alert actually means (not just "AI said suspicious")
  • Knowing when to override the AI's classification
  • Tuning AI/ML detections to reduce false positives
  • Recognizing adversarial AI — attackers trying to evade ML-based defenses

Pitfalls of AI-Driven Security Tools

  • Black box problem — hard to explain why an alert fired
  • False positives flood the queue
  • Adversarial evasion — attackers craft inputs to bypass ML
  • Bias — model trained on incomplete data misses certain attack patterns

💡 Pro tip for interviews: When asked about AI in security, don't just say "AI helps detect threats." Show nuance: "AI baselines normal behavior, but I always validate alerts because models can have false positives, and sophisticated attackers can evade ML defenses through subtle inputs."
